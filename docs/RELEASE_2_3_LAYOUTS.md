# RELEASE 2.3 — макеты страниц и ширина секций (часть B)

Часть A дала реестр тем и экран «Дизайн → Темы»: тему можно установить, переключить и
вернуть к встроенной. Каркас при этом оставался один на весь сайт — шапка, подвал и
контейнер `max-w-5xl` были у каждой страницы.

Часть B делает каркас настраиваемым: макет страницы и ширина блока.

## Что появилось

### Макет страницы (`tbl_page.layout`)

Девять макетов, каждый — набор флагов, а не отдельный шаблон:

| Ключ | Подпись | Шапка | Подвал | Каркас |
|---|---|---|---|---|
| `default` | Стандартная страница | да | да | `max-w-5xl` |
| `wide` | Широкая страница | да | да | `max-w-6xl` |
| `landing` | Лендинг без шапки и подвала | нет | нет | без отступов |
| `blank` | Пустой макет (Blank Canvas) | нет | нет | без отступов |
| `no-header` | Без шапки | нет | да | `max-w-5xl` |
| `no-footer` | Без подвала | да | нет | `max-w-5xl` |
| `sidebar-left` | Сайдбар слева | да | да | сетка с колонкой |
| `sidebar-right` | Сайдбар справа | да | да | сетка с колонкой |
| `two-sidebars` | Две боковые панели | да | да | сетка с двумя колонками |

**Неизвестное значение откатывается к `default`.** Макет приходит из базы и из формы; чужая
строка не должна оставлять страницу без шапки или давать белый экран. Проверяется это
правилом `pageLayoutPlan()`, а не доверием к значению.

**Смена макета не трогает данные.** Блоки, адрес, SEO, статус публикации и медиа остаются
прежними — меняется только обвязка вокруг содержимого. Это записано в подсказке поля формы.

### Ширина блока (`tbl_page_section.width`, `tbl_page_section.width_custom`)

| Ключ | Что делает |
|---|---|
| `standard` | Контейнер `max-w-5xl` — прежний вид всех блоков |
| `wide` | Контейнер `max-w-6xl` |
| `full` | Блок на всю ширину экрана, вложенного ограничителя нет |
| `custom` | Ширина человека, 320–2400 px, подрезается пределами |

Ширина есть **у всех** видов блоков, а не у отдельных: это свойство секции, а не вида.
Пределы `320…2400` держатся правилом: значение вне границ подрезается, а не отклоняется —
страницу уже открыли, и потерять её из-за одного числа хуже, чем подрезать.

**Full Width Section + Inner Content Container.** «Полная ширина» не печатает вложенный
контейнер вовсе: человек сам решает, ограничивать ли содержимое. Остальные ширины печатают
контейнер, и блок центрируется сам.

## Как устроено

Правила живут в `core/page-layout.php`: перечни, подписи, пределы и разбор в флаги.
Классы разметки — в теме: `theme/layout.php` (каркас), `theme/partials/section-open.php`
(контейнер блока), `theme/partials/sidebar.php` (боковая панель).

Такое разделение не косметика. Сборка стилей читает только объявленные каталоги разметки,
и класс, написанный в ядре, не попал бы в артефакт: страница потеряла бы оформление, а
страж `StyleSourceTest` покраснел бы на просвете. Первая версия части B держала классы в
ядре — страж поймал это сразу.

Новый макет добавляется строкой в `PAGE_LAYOUTS` и `PAGE_LAYOUT_NAMES`: каркас ветвится на
флагах, а не на именах макетов, поэтому шаблон править не нужно.

## Миграция

`sql/0006_release23_layouts.sql`:

```sql
ALTER TABLE tbl_page ADD COLUMN layout VARCHAR(32) NOT NULL DEFAULT 'default' AFTER noindex;
ALTER TABLE tbl_page_section
  ADD COLUMN width VARCHAR(16) NOT NULL DEFAULT 'standard' AFTER layout,
  ADD COLUMN width_custom INT NOT NULL DEFAULT 1200 AFTER width;
```

**Существующие страницы выглядят как раньше.** `default` и `standard` воспроизводят
прежний каркас и прежний контейнер `max-w-5xl`, поэтому миграция ничего не переставляет:
ни адресов, ни содержимого, ни SEO.

Файл только дополняет схему и не трогает значения других колонок.

## Совместимость с темами

Флаги макета доезжают до каркаса переменной `$layout` — тему это не ломает: старая тема,
которая не читает `$layout`, печатает свою обвязку, как раньше. Тема, которая хочет
поддержать макеты, читает `pageLayoutPlan($layout)` и сама решает, что печатать.

## Что осталось от мастер-промпта

Сделано: PHASE A (аудит), PHASE B (менеджер тем), PHASE D в части макетов и ширины.

Не сделано: PHASE C (движок шаблонов и назначение шаблонов по типам контента), PHASE E
(Template Studio — визуальный конструктор), PHASE F/G (Header/Footer Builder), PHASE H
(библиотека паттернов), PHASE I (глобальные элементы), PHASE J (Design System), PHASE K
(библиотека готовых шаблонов), PHASE L (импорт-экспорт), PHASE M (интеграция с
приложениями), PHASE N (тестирование релиза), PHASE O (релиз).

Заглушек вместо этих частей нет: экраны, которые ничего не делают, хуже их отсутствия.
