# Система тем NovaCMS

Реализовано в RELEASE 2.3 (PHASE A + B). Документ описывает то, что действительно работает,
и честно называет границы.

---

## 1. Как устроена тема

Тема — каталог в `themes/` с манифестом и каркасом:

```
themes/
  school/
    theme.json      ← манифест: идентификатор, название, версия, автор, макеты
    layout.php      ← каркас: <html>, шапка, main, подвал
    page.php        ← (необязательно) перекрывает встроенный шаблон страницы
    partials/       ← (необязательно) перекрывает партиалы
    sections/       ← (необязательно) перекрывает виды секций
```

Тема перекрывает **только те файлы, которые положила**. Нет `page.php` — берётся встроенный.
Это та же иерархия, что уже была в `resolveTemplate()`, просто к ней добавился каталог темы.

## 2. Манифест `theme.json`

```json
{
  "slug": "school",
  "name": "Школа",
  "version": "1.0.0",
  "description": "Тема школы английского",
  "author": "NovaCMS",
  "license": "MIT",
  "preview": "screenshot.png",
  "colors": {"accent": "#b45309"},
  "layouts": ["default", "landing", "full-width"]
}
```

### Обязательные поля

| Поле | Правило |
|---|---|
| `slug` | уникален, только `a-z`, `0-9`, дефис; совпадает с именем каталога |
| `name` | отображаемое название, непустое |
| `version` | строка версии (`1.0.0`) |

### Необязательные

`description`, `author`, `license`, `preview`, `colors`, `layouts`.

### Валидация

`themeManifestParse()` возвращает разобранный манифест либо текст отказа. Правила:

- битый JSON → отказ, а не «пустой манифест»;
- небезопасный `slug` (пробелы, `/`, `..`, заглавные) → отказ;
- отсутствие обязательного поля → отказ с именем поля;
- тема без `layout.php` → помечается «повреждённая» с причиной.

Отказ не роняет каталог: остальные темы остаются доступны.

## 3. Реестр и активация

- `themeRegistryRead()` читает `themes/` и делит содержимое на «годные» и «повреждённые».
- Активная тема хранится в настройке `active_theme` (`tbl_option`).
- Пустое значение = встроенная тема `theme/`.
- `themeActivate()` проверяет, что каталог и `layout.php` на месте, иначе отказ.
- `themeDeactivate()` возвращает встроенную тему.

### Что происходит при активации

1. Проверка манифеста и наличия каркаса.
2. Запись `active_theme` в настройки.
3. Запись события в журнал (`auditLog`).
4. Страница начинает рендериться каркасом темы.

### Откат

Кнопка «Сделать активной» у карточки встроенной темы снимает `active_theme`. Автоматического
отката при ошибке рендеринга **нет** — это не реализовано (см. §6).

## 4. Экран «Дизайн → Темы» (`/admin/themes`)

- карточки тем: название, версия, автор, описание, статус;
- статусы: «Активная», «Доступна»;
- кнопки «Активировать» / «Сделать активной»;
- право `manage` — переключение темы меняет весь сайт;
- плашки `theme_activated` / `theme_deactivated`.

Список тем формируется из каталога: положили каталог в `themes/` — он появился в админке.

---

## 5. Совместимость

- Пока `active_theme` пуста, поведение сайта прежнее (встроенный каркас).
- Существующие страницы, SEO, адреса и содержимое не меняются.
- Миграций схемы нет: настройка живёт в `tbl_option`, как все прочие.
- Тема не может перекрыть ядро: `resolveTemplate()` смотрит каталог темы, но не позволяет
  выйти за его пределы.

## 5.1. Design System — цвета и типографика (`/admin/design`)

Оформление темы — данные сайта, а не сборка: цвета правятся без выкладки и без пересборки CSS.

- **Палитра:** шесть переменных, те же имена, что в `@theme` (`--color-paper`, `--color-ink`,
  `--color-accent`, `--color-cream`, `--color-good`, `--color-bad`). Классы `bg-paper`, `text-ink`
  и остальные подхватывают свои значения сами — ни один шаблон править не нужно.
- **Типографика:** размеры H1–H3 и основного текста в пикселях, пределы 14–96.
- **Как применяется:** `designSystemCurrent()['css']` печатается в `$head` внутри `render()`,
  то есть **любой** темой, включая написанную до этой функции. Дублировать `<style>` в каркасе
  темы не нужно и нельзя: тема, забывшая строку, отключила бы палитру сайта.
- **Пустые значения** означают «как в теме»: переменная не печатается, работает CSS артефакта.
- **Чужое значение отбрасывается.** Поле принимает `#abc` / `#aabbcc`; строка с правилом CSS
  (`red; background: url(...)`) заменяется прежним значением — иначе через поле цвета можно было
  бы внедрить в стиль чужое объявление.
- **Контраст** считается по WCAG и показывается на экране числами: своя палитра легко даёт
  светлый текст на светлом фоне, и это видно только на живой странице.
- **Право `manage`** — палитра меняет читаемость всего сайта, как и переключение темы.

CSP разрешает `style-src 'unsafe-inline'`; `script-src 'self'` не менялся.

## 5.2. Обмен оформлением — выгрузка и ввоз файла

Экран `/admin/themes` содержит блок «Обмен оформлением»:

- **Выгрузка** — файл JSON отдаётся ответом (`Content-Disposition: attachment`, `Cache-Control: no-store`).
  На сервере ничего не создаётся: человек получает ровно то, что выбрал, и на хостинге не
  появляется каталог с чужими файлами.
- **Ввоз** — файл проверяется теми же правилами, что читают каталог тем и форму оформления:
  манифест — `themeManifestParse()`, цвета — `designColorOf()`, размеры — `designSizeOf()`.
  Палитра и типографика пишутся одной транзакцией.

**Почему JSON, а не ZIP.** Архив — это распаковка чужого содержимого: Zip Slip (`../` в имени),
символические ссылки, права файлов, типы содержимого и место, куда всё легло. Перенос оформления
файлов не требует: манифест, палитра и размеры — данные. Поэтому в модуле **нет ни одной операции
записи на диск**, и защищаться от путей негде.

**Что не переносится:** PHP каркаса, партиалы и шаблоны секций. Тема — код на сервере, и ввозить
код через форму нельзя. Файл несёт только то, что программа умеет применить списком; неизвестные
ключи (`hooks`, `routes`) выбрасываются — иначе ввоз стал бы каналом настройки сайта.

**Проверки ввоза:**

| Проверка | Поведение |
|---|---|
| Размер | больше 256 КБ — отказ до разбора JSON |
| Битый JSON | отказ, а не «пустой перенос» |
| Метка формата | не `cms-theme` — отказ (чужой файл не «применится») |
| `slug` | небезопасный (`../..`, `/`, заглавные) — отказ: имя каталога |
| Манифест | без `slug`/`name`/`version` — отказ |
| Цвет | негодное значение **отбрасывается**, файл применяется: терять всё из-за опечатки хуже |
| Размер шрифта | подрезается к пределам; ноль означает «как в теме» — ключ не переносится |

**Круг «выгрузил → ввезено» проверен тестом:** файл своей же темы обязан проходить проверку ввоза,
иначе перенос между сайтами не работал бы вовсе.

## 6. Ограничения (честно)

| Что | Статус |
|---|---|
| Установка темы из ZIP | **не реализовано** — нет защиты от Zip Slip, проверки путей и типов |
| Автоматический откат при ошибке рендеринга | **не реализовано** |
| Скриншоты тем | поле в манифесте есть, показ не сделан |
| Несколько каркасов внутри одной темы | **не реализовано** |
| Библиотека шаблонов и паттернов | **реализовано**: `/admin/templates` и `/admin/patterns` |
| Варианты шапки и подвала | **реализовано**: `/admin/settings` (готовые варианты полос) |
| Header/Footer Builder по элементам (логотип, поиск, корзина, языки) | **не реализовано** |
| Template Studio (визуальный редактор макетов) | **не реализовано** |

Установка из ZIP требует отдельного набора тестов безопасности и в этот заход не входила:
каталог `themes/` наполняется файлами на сервере, экран показывает то, что уже лежит.

| Файл | Роль |
|---|---|
| `core/theme.php` | манифест, реестр, активация |

| `core/theme-transfer.php` | выгрузка и проверка ввезённого файла |
| `core/template.php` | `render()` → `resolveTemplate('layout')`, печать стиля в `$head` |
| `core/templates/admin/themes.php` | экран каталога |
| `core/templates/admin/design.php` | экран оформления |
| `core/routes.php` | маршруты `GET/POST /admin/themes` и `/admin/design` |
| `core/notice.php` | ключи `theme_*`, `design_saved` |
| `themes/school/` | первая тема |
| `tests/unit/ThemeRegistryTest.php` | манифест и реестр |
| `tests/unit/DesignSystemTest.php` | правила палитры и типографики |
| `tests/unit/ThemeTransferTest.php` | выгрузка и защита ввоза |
| `tests/http/ThemesAdminTest.php` | экран и активация |
| `tests/http/DesignAdminTest.php` | экран оформления и печать в странице |
