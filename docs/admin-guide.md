# Руководство по админке NovaCMS

Админка открывается по адресу `/admin`; вход — `/login`, выход — `/logout`. Все экраны работают
без JavaScript: формы обычные, действия защищены токеном, а отказ всегда показывает понятную
причину. Ниже описаны вкладки ядра, вкладки пяти приложений и все виды блоков конструктора.
Дополнительные сведения о возможностях — в `README.md`, о выкладке и доступе — в
`docs/install-virtual-hosting.md`.

## 1. Вход и права

В системе две роли: **администратор** (`admin`) и **редактор** (`editor`). Заблокированная учётная
запись не пускает ни на один служебный экран. Вход и админка доступны только вошедшему сотруднику;
публичные страницы черновиков гостю не выдаются.

| Что делаете | Роль |
| --- | --- |
| Сводка, страницы и блоки, редакция, уведомления, медиатека, корзина, поиск, меню, настройки сайта, библиотека шаблонов | вошедший редактор (`login`) |
| Приложения и обновления, заявки, согласия, журнал, темы, оформление, типы контента и глобальные блоки | администратор (`manage`) |
| Записи пользовательских типов и глобальный блок на странице | вошедший редактор; публикация и архив проверяются отдельно |
| Экраны приложений | вошедший редактор; отдельные операции могут требовать администратора |

Редакционные права точнее, чем роль: администратор может всё, редактор может просматривать
историю и сравнение, восстанавливать ревизии, автосохраняться, править материал, ставить и снимать
блокировку, отправлять на проверку, читать и писать комментарии и управлять задачами. Согласование,
публикация, управление расписанием и удаление ревизий доступны только администратору. Проверки
прав серверные: интерфейс лишь показывает доступное.

## 2. Навигация

Верхняя полоса админки содержит 18 вкладок ядра в таком порядке:

| Вкладка | Адрес | Назначение |
| --- | --- | --- |
| Сводка | `/admin` | состояние сайта и версии |
| Страницы | `/admin/pages` | конструктор страниц и главной |
| Редакция | `/admin/editorial` | очередь, ревизии, согласование, комментарии, задачи, расписание |
| Контент | `/admin/content` | типы записей, записи, глобальные блоки |
| Уведомления | `/admin/notifications` | уведомления редакции |
| Медиатека | `/admin/media` | загруженные файлы |
| Корзина | `/admin/trash` | удалённые страницы и секции |
| Поиск | `/admin/search` | поиск по материалам сайта |
| Приложения | `/admin/apps` | установка и обновление разделов |
| Заявки | `/admin/leads` | заявки с форм сайта |
| Меню | `/admin/menu` | верхнее меню и меню подвала |
| Согласия | `/admin/consents` | журнал согласий на обработку данных |
| Журнал | `/admin/audit` | журнал действий сотрудников |
| Настройки | `/admin/settings` | шапка, подвал, техобслуживание |
| Темы | `/admin/themes` | реестр тем и обмен оформлением |
| Оформление | `/admin/design` | палитра и типографика |
| Шаблоны | `/admin/templates` | готовые наборы блоков |
| Паттерны | `/admin/patterns` | короткие наборы для вставки в страницу |

После установки приложений добавляются вкладки «Новости» (`/news/admin`), «Доска объявлений»
(`/classifieds/admin`), «Магазин» (`/commerce/admin`), «Курсы» (`/learn/admin`) и «SEO»
(`/seo/admin`). У каждого приложения свой второй ряд вкладок.

Зелёная плашка вверху экрана — успешное действие; красный блок с заголовком и причиной — отказ.
Обычный порядок правки: открыть экран, изменить поля, нажать «Сохранить». Порядок строк, видимость,
перемещение, дублирование и удаление — отдельные кнопки-формы: вложенные формы не допускаются,
поэтому каждое действие отправляет свой скрытый идентификатор намерения. Если два сотрудника
правили один материал, второе сохранение получает сообщение о конфликте версии — набранное не
пропадает, но перезаписывать чужую правку молча CMS не будет.

## 3. Разделы ядра

### 3.1. Сводка

Четыре карточки: сайт, администратор, число пользователей и версия PHP. Ниже — список
установленных разделов со ссылками и состоянием. Если версия PHP старее исправленной в своей
ветке, показывается красная плашка с конкретным минимумом: 8.2.35, 8.3.36, 8.4.27 или 8.5.12.
Это не косметика: установщик блокирует небезопасные версии.

### 3.2. Страницы

Список страниц со статусами, массовыми действиями и переходом в редактор. Главная — отдельная запись:
её блоки правятся на `/admin/pages/home`, у неё нет обычного адреса. У страницы поля «Заголовок»,
«Адрес», «Описание», «Статус» (черновик или опубликовано), флажок «Скрыть страницу от поисковиков»
и «Макет страницы». Адрес можно менять: прежний продолжает работать через автоматическую
301-пересылку. Служебные первые сегменты (`admin`, `login`, `news`, `shop`, `commerce`,
`classifieds`, `seo`, `learn`, `assets`, `uploads`, `sitemap` и другие) заняты маршрутами — CMS
откажет для них.

Макет меняет обвязку, не трогая блоки, адрес и SEO. Доступны девять вариантов: стандартная
страница, лендинг без шапки и подвала, пустой макет, без шапки, без подвала, широкая, сайдбар
слева, сайдбар справа, две боковые панели. Неизвестное значение откатывается к стандартному.

На экране страницы есть «Предпросмотр по ссылке»: сырая ссылка показывается один раз, живёт
семь дней, прав не даёт и хранится в базе только хешем; действующие ссылки можно отозвать.
Ниже расположены блоки страницы (см. раздел 5), буфер обмена для вставки скопированной секции
и ссылка на редакцию. Удаление уводит страницу вместе с блоками и историей адресов в корзину.

### 3.3. Редакция

Общий экран состоит из четырёх панелей: «Очередь редакции», «Последние ревизии»,
«Кто сейчас редактирует» и «Ближайшие публикации», плюс блок «Хранение истории» с настройкой
глубины. При переходе к материалу открываются:

- «Согласование» — кнопки доступных переходов с комментарием;
- «История версий» — список ревизий с восстановлением и удалением (последнее — только администратору);
- «Сравнение версий» — построчное сравнение двух выбранных ревизий;
- «Внутренние комментарии» — комментарии с упоминаниями, снятие и возврат в работу;
- «Задачи редакции» — постановка задач и смена статуса;
- «Отложенная публикация» — время публикации и отмена расписания.

Блокировка материала живёт 90 секунд и продлевается, пока сотрудник работает с формой;
присутствие — 120 секунд.
Автосохранение пишет локальный черновик и предлагает восстановить его при открытии формы;
при конфликте версий показывается отдельная плашка.

### 3.4. Контент

Главный экран показывает списки типов записей и глобальных блоков. Тип записи задаёт набор
полей; доступно десять видов: строка, многострочный текст, текст с абзацами, число, флажок,
выбор из списка, картинка, ссылка, дата и связь с записями. У записей четыре статуса: черновик,
опубликовано, запланировано, архив. Вместо удаления используется архив. У записей и глобальных
блоков есть ревизии и те же правила редакции, что у страниц.

Глобальный блок — отдельная сущность с фиксированным набором полей: заголовок, подзаголовок,
текст, картинка, описание картинки, ссылка и подпись кнопки. Вёрстка выбирается из четырёх
вариантов: текст, картинка слева, картинка справа, баннер. Блок вставляется в страницу видом
«Глобальный блок» по его адресу (слагу). Пустой, неизвестный или архивный слаг ничего не печатает.

### 3.5. Уведомления

Центр уведомлений редакции: список событий с отметками прочитанного и действиями «прочитать всё».
Сюда приходят упоминания в комментариях, задачи и события согласования.

### 3.6. Медиатека

Список загруженных файлов с превью, загрузка новых файлов и правка описания картинки (ALT).
Экран показывает, где файл используется: удалить файл, на который ссылаются материалы, нельзя —
сначала правят ссылки. Картинки принимаются в форматах jpg, png и webp размером до 5 МБ.

### 3.7. Корзина

Удалённые страницы и секции со ссылками на место, откуда они пришли. Восстановление возвращает
объект на прежнее место; очистка корзины удаляет окончательно. Шаблон «заменить блоки» тоже
отправляет прежние блоки сюда, поэтому собранную страницу можно вернуть.

### 3.8. Поиск

Одна строка поиска по материалам сайта; результаты сгруппированы по разделам. Поиск работает с
первого ввода, спецсимволы `%` и `_` ищутся как обычный текст.

### 3.9. Приложения

Карточки пяти разделов с версиями. Кнопки «Установить» и «Обновить» появляются по состоянию:
установка доступна, если раздела нет, обновление — если версия в манифесте выше установленной.
Манифест объявляет требуемую версию ядра: если она выше текущей, установка отказывает человеческим
текстом и таблицы не создаёт. Повторная установка не дублирует журнал миграций. Если программу
курсов приносит перенос данных, «Курсы» ставятся без начальных данных, иначе начальный набор займёт
уровень Pre-A1 и вызовет конфликт.

### 3.10. Заявки

Фильтры «Новые», «Обработанные», «Все», поиск по имени и контакту, 25 заявок на страницу. У заявки
можно сменить статус, удалить её и ответить письмом из админки — форма ответа приходит с готовым
черновиком. Приём заявок ограничен пятью в час с одного адреса; согласие на обработку данных
обязательно и проверяется и браузером, и сервером.

### 3.11. Меню

Две вкладки: «Верхнее меню» и «Меню в футере». В каждой — список пунктов с подписью, адресом,
порядком и флажком видимости. Пустые колонки подвала не печатаются; кнопка входа остаётся в шапке
при любом варианте её вёрстки.

### 3.12. Согласия

Журнал согласий на обработку данных: кто, когда и с какой формы дал согласие. Раздел доступен
администратору; записи нужны для подтверждения факта согласия, а не для рассылки.

### 3.13. Журнал

Журнал действий сотрудников: вход, сохранения, публикации, удаления, обновления разделов.
Фильтры по действию и пользователю помогают восстановить, кто и когда изменил материал.
Доступен администратору.

### 3.14. Настройки

Одна форма на шапку, подвал и техобслуживание. Шапка: вид полосы (стандартная, минималистичная,
по центру, с верхней строкой), логотип (путь или файл jpg/png/webp до 5 МБ), текст. Подвал: вид
(стандартный, компактный, без колонок меню), логотип, подпись, копирайт. Неизвестное значение
варианта означает стандартный вид — подделанная форма не оставит сайт без шапки.

Флажок «Включить режим техобслуживания» закрывает публичную часть заглушкой со статусом 503,
заголовками `noindex` и `no-store` и `Retry-After`. Вход и админка остаются открытыми, и вошедший
сотрудник видит сайт как обычно — иначе режим нечем снять и нельзя проверить вёрстку перед
открытием. Текст заглушки правится здесь же; пустое поле означает запасной текст.

Почтовые ключи и адрес сайта здесь не правятся: они лежат в `config.php` на сервере.

### 3.15. Темы

Карточки установленных тем с отметкой активной и кнопкой активации. Испорченные темы
перечислены отдельно с причиной: один битый манифест не роняет весь каталог. Блок «Обмен
оформлением» выгружает палитру и размеры файлом JSON и ввозит его обратно. Файл больше 256 КБ,
битый JSON и чужой формат отклоняются; PHP-код темы не переносится — тема живёт на сервере.

### 3.16. Оформление

Шесть цветовых переменных палитры и размеры H1, H2, H3 и основного текста. Своё значение
печатается для любой темы, включая ту, что написана раньше. Пустое поле означает «как в теме».
Негодное значение цвета отбрасывается: через поле нельзя внедрить чужое CSS-правило. На экране
показывается контраст по WCAG числами — светлый текст на светлом фоне сразу виден.

### 3.17. Шаблоны

17 готовых наборов блоков в 16 категориях: главная школы, курс, лендинг продажи, контакты,
о компании, услуги, тарифы, вопросы и другие. Выберите шаблон и страницу. По умолчанию блоки
**добавляются** к существующим; замена включается отдельным флажком и убирает прежние блоки в
корзину. Применение идёт одной транзакцией, предел в 40 секций проверяется до вставки. Собранная
страница правится в обычном конструкторе — второго редактора разметки нет.

### 3.18. Паттерны

Каталог коротких наборов для вставки в уже собранную страницу: вступление, три преимущества,
три шага, три вопроса, три тарифа, отзывы, контакты, галерея, форма заявки и призыв к действию.
Фильтр по категориям работает так же, как у шаблонов. В паттерне один-три блока конструктора; он
ничего не заменяет и не меняет макет страницы. Якоря паттернов начинаются с `p-` и не пересекаются,
поэтому на страницу можно поставить несколько наборов. Вставка идёт одной транзакцией, предел
в 40 блоков проверяется до вставки. После вставки открывается редактор страницы. Право то же, что
у конструктора (`login`).

## 4. Разделы приложений

### 4.1. Новости (`/news/admin`)

Пять вкладок:

- **Сводка** — счётчики материалов и рубрик, число закреплённых.
- **Материалы** — фильтры по статусу и рубрике, поиск, постраничный список. Форма материала:
  заголовок, адрес, лид, абзацы (до 40), обложка, теги через запятую (до 10), срок публикации,
  закрепление, SEO-заголовок, SEO-описание, `noindex`. Кнопки «Сохранить черновик» и «На печать»;
  черновик без текста проходит, печать без текста — нет. Смена адреса сохраняет прежний (до
  10 адресов) и отвечает 301.
- **Рубрики** — название, адрес, описание, порядок и скрытие. Переименование не меняет адрес;
  удаление непустой рубрики отказывает.
- **Теги** — справочник названий; новые теги заводятся из формы материала автоматически.
- **Блоки** — по одной таблице на зону «На главной», «В рубрике», «В материале». У блока:
  заголовок, вид («Список материалов» или «Похожие материалы»), цель отбора (весь раздел,
  рубрика или тег), число материалов, видимость и порядок стрелками.

### 4.2. Доска объявлений (`/classifieds/admin`)

Семь вкладок: **Обзор** (счётчики и быстрые ссылки), **Категории** (дерево, порядок, видимость),
**Характеристики** (поля категорий: подпись, тип, единица, варианты), **Проверка** (очередь
модерации: одобрить, отклонить, запросить правки), **Жалобы** (жалобы на объявления и решения по
ним), **Продвижения** (поднятые объявления и сроки) и **Вебхуки** (адреса и события уведомлений).
Объявления содержат цену, пометку «торг», город, фотографии и характеристики категории.

### 4.3. Магазин (`/commerce/admin`)

Девять вкладок: **Обзор**, **Товары**, **Рубрики**, **Купоны**, **Промо-правила**,
**Поставщики**, **Прайс-лист**, **Webhooks**, **Заказы**.

Форма товара: название, артикул (SKU), адрес страницы, бренд, штрихкод, краткое описание,
розничная и промо-цена, себестоимость, остаток, статус, рубрики и характеристики; варианты
правятся отдельной ссылкой. У товара два статуса — «Черновик» и «Публикуется»; заказ проходит «Новый»,
«Оплачен», «Отправлен», «Доставлен» или «Отменён». Купоны задают код и скидку, промо-правила —
условия применения,
поставщики и прайс-лист — закупочные данные, вебхуки — адреса событий каталога и заказов.
Адрес вебхука проверяется: внутренние диапазоны, логин с паролем в адресе и имена, разрешающиеся
внутрь, отклоняются.

### 4.4. Курсы (`/learn/admin`)

Три вкладки: **Сводка** (число уровней, курсов, модулей и уроков), **Уровни и курсы** (дерево
«уровень → курс → модуль» с созданием, сохранением, перемещением и удалением) и **Уроки**
(список с путём «уровень › курс › модуль» и формой урока). У урока: адрес, название, описание,
модуль, статус, цели, лексика с транскрипцией, грамматика, упражнения восьми типов и мини-тест.
Удаление урока со всеми вложениями требует подтверждения и не отменяется.

### 4.5. SEO и статистика (`/seo/admin`)

15 вкладок:

## 5. Конструктор страниц и виды блоков

### 5.1. Общие правила

Страница собирается из блоков (секций). У блока есть вид, якорь, заголовок, подзаголовок и текст;
абзацы в тексте разделяются пустой строкой. Дополнительные поля появляются только у того вида,
который их читает: человек не правит то, что никуда не попадёт.

| Поле | Назначение и предел |
| --- | --- |
| Якорь | ссылка на место страницы `/адрес#якорь`; до 40 символов, пустой собирается из заголовка |
| Заголовок секции | до 160 символов |
| Подзаголовок (бейдж) | до 80 символов |
| Текст (лид) | до 1000 символов, абзацы через пустую строку |
| Примечание | до 200 символов, сноска под блоком |
| Картинка и её описание | путь на сайте или файл jpg, png, webp до 5 МБ; описание до 160 символов |
| Кнопки | до четырёх: подпись (до 60), адрес, флажок «Новая вкладка» |
| Строки | до 40 на блок; поля строки зависят от вида, заголовок строки до 120, текст до 600 |
| Visible | флажок «Показывать на странице»; скрытый блок остаётся в конструкторе |
| Вёрстка | только у «Картинки с обтеканием» и «Файлов» |
| Ширина блока | у всех видов: стандартная, широкая, во всю ширину, своя (320–2400 px) |

На страницу можно добавить до 40 секций; предел проверяется до вставки и перечитывается при
одновременной правке. Действия с блоком: выше, ниже, скрыть/показать, дублировать, скопировать в
буфер, вставить, удалить. Блоки сворачиваются, и сохранённая свёрнутость переживает перезагрузку.
Смена вида доступна селектом; поля нового вида появятся после сохранения и перезагрузки.

В таблице «Строки» перечислены поля повторяющейся строки. Общие поля шапки и кнопки перечислены
выше и в списке видов не повторяются.

| Вид в конструкторе | Поля строки | Как используется |
| --- | --- | --- |
| Большой первый экран | — | `h1`, лид, примечание, картинка, кнопки; единственный `h1` на странице |
| Полоса с текстом | — | светлая полоса, заголовок по центру, лид и примечание |
| Карточки | Картинка, заголовок, текст, адрес ссылки, подпись | сетка карточек; заголовок становится ссылкой, если задан адрес |
| Шаги | Шаг, описание | нумерованный список; номер ставится автоматически |
| Текстовый блок | — | заголовок, абзацы лида и мелкая сноска |
| Текст и картинка | Пункт, пояснение | текст слева с пунктами и кнопками, картинка справа; без картинки блок в одну колонку |

| Соседние ссылки | Адрес, заголовок ссылки, пояснение | «смотрите также»; строка без адреса не печатается |
| Ведомость | Название, значение, примечание | двухколоночная таблица характеристик со сноской |

| Файлы | Плашка, адрес файла, название, описание, примечание | список или карточки; плашка собирается из расширения, если не задана |
| Контакты | Подпись, адрес ссылки, значение, примечание | телефон, почта, адрес карты; значение со ссылкой становится активным |

| Призыв к действию | — | тёмная полоса по центру с инвертированными кнопками |
| Вопросы и ответы | Вопрос, ответ | пары вопрос-ответ плюс разметка `FAQPage`; вопрос без ответа в разметку не идёт |
| Форма заявки | Пункт | обещания слева и форма справа, согласие обязательно, ловушка для ботов |
| Партнёры | Логотип, название, адрес сайта, подпись | сетка логотипов; без картинки показывается монограмма |
| Поделиться | — | ссылки на мессенджеры и сети без скрипта, адрес берётся без строки запроса и якоря |

### 5.3. Блоки приложений

Эти виды появляются в селекте только когда соответствующее приложение установлено.

| Вид | Настройки в блоке «Настройки вклада» | Поведение |
| --- | --- | --- |
| Новости — лента (`news_feed`) | «Сколько материалов» (1–12), «Рубрика» (адрес; пусто — вся лента), «Вариант вёрстки» (пока один) | печатает живые материалы по настройкам; ядро хранит их как есть |
| Курсы — карта уровней (`learn_levels`) | «Сколько уровней», «Подпись кнопки», «Адрес кнопки» (например `/placement-test`) | ступени и число уроков берутся из таблиц курсов; пустая подпись убирает кнопку |
| Глобальный блок (`global_block`) | «Блок» — слаг из раздела «Контент → Глобальные блоки» | печатает содержимое глобального блока; пустой, неизвестный или архивный слаг не печатает ничего |

Все три вида получают общие поля шапки; остальные настройки рисует само приложение. Пустые
строки и неполные записи в перечисленных видах пропускаются — страница не обрастает пустыми
рамками.

## 6. Редакционный процесс

Статусы материала: «Черновик» → «На проверке» → «Возвращено на доработку» → «Одобрено» →
«Запланировано» → «Опубликовано» или «Снято с публикации». Редактор готовит материал и отправляет
на проверку; администратор согласовывает, публикует или возвращает на доработку. Публикацию можно
отложить: `bin/cron.php` (раз в минуту) находит очередь и снимает материал в назначенное время.
Без cron отложенные публикации остаются в очереди.

Каждое сохранение создаёт ревизию; две ревизии можно сравнить построчно и восстановить прежнюю.
Восстановление само записывается как новая ревизия — история не теряется. Комментарии с
упоминаниями и задачи живут внутри редакции, публичных адресов у них нет. Уведомления о событиях
приходят в «Уведомления». Если сотрудник открыл материал, ставится блокировка на 90 секунд с
продлением; второй сотрудник видит, кто правит материал, и не может перезаписать его молча.

Тот же процесс работает для пользовательских типов записей и глобальных блоков.

## 7. Частые задачи

| Задача | Порядок |
| --- | --- |
| Создать страницу | «Страницы» → форма страницы → заголовок, адрес, статус → «Сохранить страницу» → добавить блоки |
| Добавить блок | на странице выберите вид внизу формы блока, заполните поля, нажмите «Сохранить блок» |
| Поменять картинку | в поле «Картинка» нажмите кнопку с иконкой папки и выберите файл; путь подставится после сохранения |
| Изменить адрес страницы | Правьте поле «Адрес»; прежний адрес продолжит работать через 301 |
| Сделать общий текстовый блок | «Контент» → «Глобальные блоки» → создайте блок → на странице добавьте «Глобальный блок» с его слагом |
| Поставить готовую страницу | «Шаблоны» → выберите шаблон и страницу → при необходимости включите замену (прежние блоки уйдут в корзину) |
| Добавить готовый кусок | «Паттерны» → выберите паттерн и страницу → блоки добавятся в конец, прежнее содержимое не тронется |
| Восстановить удалённое | «Корзина» → найдите страницу или секцию → «Восстановить» |
| Сменить оформление | «Темы» → активируйте тему; палитру и размеры правьте в «Оформлении»; обмен JSON — на экране тем |
| Опубликовать материал | «Редакция» → материал → «На проверке» → администратор: «Одобрено» → «Опубликовано» |
| Установить раздел | «Приложения» → «Установить» у нужной карточки; обновление доступно при новой версии в манифесте |
