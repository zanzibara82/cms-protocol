# RELEASE 2.3 — аудит системы оформления (Theme & Template Studio)

Дата аудита: 14 ноября 2026. Ревизия кода: `d82dff4` + незакоммиченная работа этого захода.

Документ отвечает на вопрос «что уже есть в оформлении NovaCMS и что нужно менять, чтобы
появилась система тем и шаблонов». Все утверждения ниже проверены по коду, а не по планам.

---

## 1. Текущая архитектура оформления

### 1.1. Один каталог темы, один каркас

Оформление живёт в `theme/`:

| Файл | Роль |
|---|---|
| `theme/layout.php` | единственный каркас: `<html>`, шапка, `main`, подвал |
| `theme/page.php` | страница из секций |
| `theme/home.php` | главная |
| `theme/sections/*.php` | 24 вида секций конструктора |
| `theme/partials/*.php` | шапка, подвал, партиалы разметки |

`render()` в `core/template.php` заканчивался **прямым** `require` этого файла:

```php
require dirname(__DIR__) . '/theme/layout.php';
```

Это ключевое ограничение: как бы ни называлась настройка темы, каркас всегда был один и тот же файл.

### 1.2. Что уже переиспользуется

- `partial()` / `resolveTemplate()` — иерархия шаблонов уже есть, но каталог у неё один.
- Конструктор секций: 24 вида, `pagesSectionsHtml()`, двухпроходная сборка с оглавлением.
- Медиатека, загрузка картинок, ревизии, редакционный центр, глобальные блоки.
- `config.php`-независимые настройки через `tbl_option` (`optionsRef()`, `getOption()`, `setOption()`).
- Стражи разметки: `StyleSourceTest`, `TapTargetTest`, `AdminFormSpacingTest`, `CheckboxAlignTest`,
  `ViewportMetaTest`, `AdminGridOverflowTest`, `ResponsiveCoverageTest`.

### 1.3. Ограничения, найденные аудитом

1. **Каркас жёстко зашит** — `render()` не пользовался `resolveTemplate()`. Любая «тема» была бы
   декоративной.
2. **Нет манифеста** — у темы нет ни идентификатора, ни версии, ни списка возможностей. Нечего
   валидировать при установке.
3. **Нет реестра** — админка не знает, какие темы существуют: список взять неоткуда.
4. **Нет ширины секции** — `page.php` печатает секции подряд, у секции нет поля ширины.
   Full Width из §7 мастер-промпта невыразим.
5. **Нет макетов страниц** — нет ни `layout`, ни выбора «сайдбар слева/справа/без шапки».

## 2. Что сделано в этом заходе (PHASE A + B)

### 2.1. Реестр тем — `core/theme.php`

- `themeManifestParse()` — разбор и валидация `theme.json`: идентификатор, название, версия,
  описание, автор, лицензия, поддерживаемые макеты, параметры. Отказ возвращается значением,
  а не исключением: одна битая тема не должна ронять каталог.
- `themeRegistryRead()` — читает `themes/`, различает «годная» и «испорченная» (с причиной).
- `themeActivate()` / `themeDeactivate()` — активация с проверкой, что каталог и каркас на месте.
- Настройка хранится в `tbl_option` под ключом `active_theme`; пустое значение = встроенная тема.

### 2.2. Каркас ищется по иерархии

`render()` теперь вызывает `resolveTemplate('layout')`, а `resolveTemplate()` первым делом
смотрит каталог активной темы. Переключение темы меняет страницу по-настоящему.

### 2.3. Экран «Дизайн → Темы» — `/admin/themes`

- карточки: название, версия, автор, описание, статус (активная / доступная);
- кнопки «Активировать» и «Сделать активной» (возврат к встроенной);
- право `manage` — переключение темы меняет оформление всего сайта, это решение администратора;
- плашки `theme_activated` / `theme_deactivated`, запись в журнал (`auditLog`).

### 2.4. Первая тема — `themes/school/`

- `theme.json` с манифестом;
- `layout.php` — широкий контейнер `max-w-6xl` и акцентная полоса под шапкой.

Проверено на живом стенде: после активации главная отдаёт `max-w-6xl` и `bg-accent`, после
возврата — снова `max-w-5xl`.

## 3. Совместимость со старой темой

- Встроенный `theme/layout.php` остаётся **каркасом по умолчанию**: пока `active_theme` пуста,
  поведение байт-в-байт прежнее.
- Тема перекрывает только те файлы, которые положила. Нет `page.php` — берётся встроенный.
- Существующие страницы, SEO, адреса и содержимое не меняются: миграций схемы нет.
- Настройка `active_theme` не создаётся заранее — её отсутствие читается как «встроенная тема».

## 4. Что осталось за границей этого захода

Мастер-промпт RELEASE 2.3 описывает 15 фаз. Честный статус:

| Фаза | Статус |
|---|---|
| A — аудит | **сделано** (этот документ) |
| B — Theme Manager | **сделано частично**: реестр, манифест, активация, экран. Установка из ZIP — нет |
| C — Template Engine | не начато |
| D — Page Layout / Full Width | не начато |
| E — Template Studio | не начато |
| F — Header Builder | не начато |
| G — Footer Builder | не начато |
| H — Pattern Library | не начато |
| I — Global Elements | частично есть (`global_block` из RELEASE 2.3) |
| J — Design System | не начато |
| K — Template Library | не начато |
| L — Import/Export | не начато |
| M — Integration | каркас интегрирован, остальное нет |
| N — Testing | покрыто то, что сделано (unit + http + стражи) |
| O — Release | нет |

### 4.1. Чего сознательно нет в установке темы

Установка из ZIP требует защиты от Zip Slip, проверки путей, ограничения размера и типов файлов.
Это отдельная работа с собственным набором тестов — в этом заходе её нет. Каталог `themes/`
пока наполняется файлами на сервере; экран показывает то, что уже лежит.

### 4.2. Причина не делать всё сразу

Каждая фаза мастер-промпта — это самостоятельный слой с миграциями, правами и тестами. Слой
макетов (D) меняет `tbl_page` и шаблон страницы, то есть трогает все существующие страницы.
Делать его «заодно» с реестром тем — значит менять данные без миграции и без проверки
совместимости, что прямо запрещено §25 промпта.

## 5. Следующий шаг по плану

Порядок, который не ломает существующие страницы:

1. **D — макеты страниц.** Поле `layout` в `tbl_page` со значением `default` по умолчанию
   (миграция только дополняющая), выбор макета в редакторе страницы, каркасы `layout-*`.
2. **Full Width.** Поле `width` у секции (`standard`/`wide`/`full`/`custom`) — §7 промпта.
3. **C — назначение шаблонов** поверх макетов.
4. **E — Template Studio** — только после того, как макеты и ширина работают.

Порядок выбран так, чтобы каждый шаг давал работающую функцию и не требовал отката.
