# CMS на PHP: ядро и раздел «Новости» — дизайн пилота

**Дата:** 2026-10-06
**Статус:** принят в мозговом штурме (разделы 1–3 подтверждены), ждёт вычитки человеком
**Источник правил раздела «Новости»:** `english-portal/docs/superpowers/specs/2026-10-04-news-app-design.md`
и код `english-portal/src/apps/news` (3 409 строк) с его 452 тестами — эталон поведения, а не память.

## 1. Цель

Сделать CMS на PHP и MySQL, которая целиком работает на виртуальном (shared) хостинге —
без долгоживущего процесса, без Docker, без Node на сервере, — и при этом сохраняет всё, что
умеет текущий портал: личный кабинет с прогрессом, админку курсов и CMS-страниц, доску
объявлений с модерацией, магазин с заказами, новости с формой материала и рассылку ответов
на заявки. Архитектура — по образцу WordPress: ядро не правят, разделы живут в приложениях
и подключаются через точки расширения.

**Пилот** (этот документ) — ядро плюс один раздел, «Новости». Остальные разделы портируются
после пилота, каждый своим планом.

## 2. Почему не Next.js на shared-хостинге

Виртуальный хостинг TimeWeb: MySQL 5.7/8.0, PHP с поддержкой фреймворков, cron, SSH,
бесплатный SSL, почта домена (до 2000 писем в сутки), лимит памяти 1024 МБ на процесс.
Node.js доступен через `nvm`, но документация хостинга прямо запрещает запуск в виде
системной службы или веб-сервера. Next.js — это долгоживущий сервер, поэтому на таком
хостинге возможен только статический экспорт, а он отбирает кабинет, админку, формы и
действия. PHP работает от запроса до запроса — под ограничения хостинга подходит.

## 3. Не-цели пилота

- Перенос данных из PostgreSQL: база стартует пустой, контент пилота набирается через админку.
- Разделы «Курсы», «Кабинет», «Доска», «Магазин», «Заявки», CMS-страницы из блоков и живые
  блоки конструктора — свои планы после пилота.
- Очереди, кеш-слой, REST API, мультисайт, переводы интерфейса.
- Задачи 18–21 текущего Next.js-плана не отменены: портал остаётся на `main` (`75397bd`),
  живая база в состоянии «новости не установлены», к задачам возвращаемся после пилота.

## 4. Платформа и ограничения среды

| Ограничение хостинга | Как учитываем |
|---|---|
| Нет долгоживущего процесса | Каждый запрос обрабатывает `public/index.php` и завершается; никакого кеша в памяти между запросами |
| 1024 МБ на процесс | Никакой сборки на сервере: CSS собран локально, зависимости dev-only |
| Только MySQL | Одна база, префикс имён таблиц вместо схем PostgreSQL |
| Нет Node | Tailwind собирается локально, в репозитории лежит готовый CSS |
| `mail()` ненадёжна | Свой SMTP-клиент на `stream_socket_client`, порт 587, STARTTLS |
| cron доступен, но не нужен пилоту | Видимость по сроку вычисляется при запросе (`visibleWhere(now)`), фоновых задач нет |
| Документ-корень не всегда переносится | Два варианта раскладки, оба в `scripts/deploy.sh` |

Целевая версия PHP — 8.3, минимально поддерживаемая — 8.1. В каждом файле
`declare(strict_types=1)`. Стиль — близкий к PSR-12.

## 5. Архитектура

### 5.1 Каталоги

```
cms/
  public/            заливается на хостинг: index.php, .htaccess, assets/, uploads/, setup.php
  core/              bootstrap, router, db, hooks, template, auth, csrf, mailer, apps, migrations, options, id, request, response, view-хелперы
  admin/             каркас админки: layout, панели, таблицы, формы, уведомления, раздел «Приложения»
  theme/             наша вёрстка: layout, шапка, футер, дизайн-система, кот
  apps/news/         manifest.php, routes.php, actions/, lib/, templates/, sql/, seed.php
  sql/               миграции ядра
  tests/             PHPUnit: unit, guard (сканирование исходников), http
  scripts/           deploy.sh, css (сборка Tailwind), db-reset (только cms_test)
  config.sample.php  образец настроек (в репозитории)
  config.php         боевые настройки (вне репозитория, права 600)
  composer.json      только require-dev: phpunit, phpstan, php-cs-fixer
```

`public/` — единственное, что видит веб-сервер. `config.php`, `core/`, `apps/`, `sql/`,
`tests/` лежат вне документ-корня; если хостинг не даёт перенести корень на `public/`,
структура кладётся целиком, а служебные каталоги закрывает `.htaccess` с `Require all denied`.

### 5.2 Путь запроса

1. `public/index.php` читает `config.php`, подключает `core/bootstrap.php`.
2. `bootstrap.php`: автозагрузка классов, часовой пояс (`Europe/Moscow` для вывода,
   хранение в UTC), обработчики ошибок и исключений, подключение `core/hooks.php`.
3. Старт сессии с безопасными флагами cookie.
4. `core/apps.php` читает манифесты включённых приложений и собирает таблицу маршрутов;
   порядок регистрации — ядро, затем приложения по алфавиту `id`.
5. `core/router.php` сопоставляет `REQUEST_URI` с маршрутами, извлекает параметры.
6. Гейты: приложение установлено и включено → путь не приватный для анонима → есть право.
7. `do_action('before_route', $route)`.
8. Действие: для GET — функция-контроллер приложения, для POST — обработчик из `actions/`.
9. `render('news/single', $data)` выбирает шаблон по иерархии, оборачивает в layout.
10. `do_action('after_route')`, вывод.

Несовпадение маршрута — `404.php` со статусом 404. Исключение — страница 500 с записью в
журнал `core/storage/errors.log` (каталог вне web-корня), наружу — только «что-то сломалось»,
без дампа стека.

### 5.3 Маршруты

Ядро:

| Адрес | Что |
|---|---|
| `/` | главная (в пилоте — заглушка темы со ссылкой на ленту) |
| `/login`, `/logout` | вход и выход администратора и редактора |
| `/admin` | сводка админки |
| `/admin/apps` | приложения: установка, включение, «Обновить» |
| `/sitemap.xml`, `/robots.txt` | собираются из хуков приложений |
| `*` | `404.php` |

«Новости»:

| Адрес | Что |
|---|---|
| `/news` | лента с пагинацией, поиском и фильтром |
| `/news/{slug}` | карточка материала |
| `/news/c/{slug}` | страница рубрики |
| `/news/t/{slug}` | страница тега |
| `/news/admin` | сводка раздела |
| `/news/admin/items`, `/items/new`, `/items/{id}` | список, создание, правка |
| `/news/admin/categories`, `/news/admin/tags` | справочники |

Служебные сегменты `admin`, `c`, `t` зарезервированы: адрес материала не может их занимать
(иначе новость «admin» спрятала бы админку). Проверка — в `validators.php` и в тесте.

### 5.4 Хуки

`core/hooks.php`: `add_action(string $hook, callable $fn, int $priority = 10)`,
`add_filter(...)` — то же, `do_action(string $hook, ...$args)`,
`apply_filters(string $hook, $value, ...$args)` (фильтр обязан вернуть значение).
Вызов с приоритетом по возрастанию; один хук можно зарегистрировать несколько раз.

Точки ядра в пилоте: `before_route`, `after_route`, `page_head`, `page_footer`,
`admin_nav`, `sitemap_urls`, `robots_lines`, `notice_text`, `before_mail_send`,
`app_installed`, `app_updated`, `form_field_error`.

### 5.5 Манифест приложения

`apps/news/manifest.php` возвращает массив:

```php
return [
  'id' => 'news',
  'title' => 'Новости',
  'version' => '1.0.0',
  'requiresCore' => '1.1.0',
  'privatePaths' => ['/news/admin'],
  'sql' => __DIR__ . '/sql',
  'adminNav' => [ /* вкладки раздела */ ],
  'seed' => __DIR__ . '/seed.php',
];
```

`core/version.php` несёт `CORE_VERSION = '1.1.0'`. Правило: приложение устанавливается
только если `requiresCore <= CORE_VERSION`; иначе — человеческий текст «нужна версия ядра
не ниже X, в сборке Y».

### 5.6 Шаблоны и тема

`render(string $template, array $data = [])` ищет файл по цепочке и берёт первый найденный:
`apps/<приложение>/templates/<имя>.php` → `theme/<приложение>/<имя>.php` →
`core/templates/<имя>.php` → `theme/404.php`. Частичные шаблоны — `partial('news/card', $item)`.
Layout — `theme/layout.php`, принимает `$title`, `$description`, `$content`, `$head` (OG, robots).

Весь вывод — через `e()` (`htmlspecialchars` с `ENT_QUOTES | ENT_SUBSTITUTE`, UTF-8).
Страж запрещает в шаблонах `echo $` и `<?=` без `e(`, кроме мест, помеченных
`/* @safe html */` (разметка блоков с выделением `**текст**`).

### 5.7 Статика и дизайн

Tailwind собирается локально (`scripts/css`, Node нужен только разработчику) в
`public/assets/app.css`; в репозитории лежат и `tailwind.config.js`, и собранный файл.
Дизайн-система, кот, цвета, шрифты и адаптивность 360…1440 переносятся из
`english-portal/public` и `src/app/globals.css` как есть.

## 6. Данные

### 6.1 Правила

- Одна база MySQL, InnoDB, `utf8mb4` / `utf8mb4_unicode_ci`.
- Префикс таблиц из `config.php` (по умолчанию `tbl_`), в запросах — только через `t('news_item')`.
- Идентификаторы — строки `VARCHAR(26)`, генератор `core/id.php`: 26 символов, сортируемый
  по времени (первые 10 символов — время в base32, дальше случайные). Причина: перенос данных
  из PostgreSQL сохранит те же ключи, а `AUTO_INCREMENT` при восстановлении из дампа порядок не гарантирует.
- Даты — `DATETIME` в UTC; перевод в `Europe/Moscow` только на краях (вывод, разбор даты формы).
- Булевы — `TINYINT(1)`. Перечисления — `VARCHAR` со справочником значений в PHP: `CHECK`
  в MySQL 5.7 молча игнорируется, поэтому правило живёт в коде и сторожится тестом.
- Миграции только дополняющие: ни `DROP`, ни `TRUNCATE`, ни `DELETE FROM` в `sql/`.
- Никакого склеивания строк в SQL: только плейсхолдеры. Поиск через `escapeLike()`
  (экранирует `%`, `_`, `\`).

`tbl_news_old_slug` заменяет `String[] oldSlugs` из PostgreSQL: в MySQL поиск по JSON-массиву
без индекса — сканирование таблицы на каждом открытии старого адреса. Лимит «не больше 10 на
материал» проверяет `rememberOldSlug()` в PHP.

`body` — JSON-массив абзацев `[{title, text}]`; сырого HTML в материале нет, выделение
задаётся `**звёздочками**` и разбирается при выводе. Валидность JSON проверяет PHP перед записью.

### 6.3 Установка и обновление приложений

`setup.php` (одноразовый): проверяет версию PHP и расширения, создаёт таблицы ядра из
`sql/0001_core_baseline.sql`, спрашивает имя сайта, email и пароль администратора, пишет
`tbl_option` и `tbl_user` с ролью `admin`, создаёт `public/install.lock`. После появления
замка скрипт отвечает 404.

`core/migrations.php`: `planApp(string $app): Plan` — список ещё не применённых файлов из
`sql/` приложения, сверка контрольных сумм уже применённых (sha256 текста файла);
`applyApp(Plan): Result` — транзакция PDO: применить файлы по порядку → записать строки в
`tbl_app_migration` → поднять `tbl_app_installation.version` → `do_action('app_updated')`.
Изменившийся применённый файл — отказ с текстом «файл миграции X изменён после применения»,
а не тихая перезапись.

Первая установка приложения дополнительно запускает его `seed.php` (однократно, в той же
транзакции): у «Новостей» он создаёт три стартовые рубрики. `seed.php` только добавляет
строки — повторный запуск не дублирует их (проверка по уникальному `slug`).

`/admin/apps` показывает список приложений из манифестов: состояние (не установлено /
установлено / требует обновления / выключено), версия в базе против версии манифеста,
кнопки «Установить», «Обновить», «Выключить», «Включить». Установка доступна только при
`requiresCore <= CORE_VERSION`.

## 7. Безопасность

- Сессия: `session.cookie_httponly = 1`, `cookie_samesite = 'Lax'`, `cookie_secure` при HTTPS,
  `use_strict_mode = 1`. Отзыв — увеличением `session_version` пользователя.
- Пароли: `password_hash(PASSWORD_ARGON2ID)`, при отсутствии расширения — `PASSWORD_BCRYPT`;
  проверка `password_verify` + `password_needs_rehash`. Наличие Argon2id проверяется на
  хостинге до деплоя (пункт чек-листа, раздел 11).
- Роли пилота: `admin` (всё) и `editor` (разделы контента). Право проверяет `getEditorAccess()` —
  аноним или заблокированный пользователь получает редирект на `/login`, а на приватном пути
  админки раздела — 403 без содержимого.
- Брутфорс: не больше 5 неудачных попыток на email за 15 минут и 20 на IP за час;
  IP берётся только из `REMOTE_ADDR`, `x-forwarded-for` не читается нигде (страж).
- CSRF: токен в сессии, скрытое поле `_token` в каждой форме, проверка в каждом POST-обработчике;
  несовпадение — 403 и запись в журнал.
- Формы: `method="post"` для всех, где есть пароль или изменение данных; намерение кнопки —
  отдельное поле `intent` или `op`; после успеха — PRG-редирект с `?notice=<ключ>`.
- Загрузки: `public/uploads/news/<сгенерированное-имя>.<расширение>`; MIME проверяется по
  содержимому (`finfo`), размер ≤ 5 МБ, расширение из белого списка `jpg, jpeg, png, webp`;
  путь из формы не используется (защита от path traversal).
- Заголовки ответа (в `.htaccess` и/или в `bootstrap.php`): `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: SAMEORIGIN`,
  `Content-Security-Policy` — переносится из текущего проекта.
- Приватные пути из манифестов (`/news/admin`) попадают в `robots.txt` как `Disallow`,
  а их страницы несут `<meta name="robots" content="noindex, nofollow">`.
- `setup.php`, `config.php`, `sql/`, `tests/`, `core/`, `apps/` недоступны по HTTP.

## 8. Раздел «Новости»

Правила переносятся из спецификации 2026-10-04 без изменений; ниже — сводка того, что
обязано работать в пилоте.

### 8.1 Пределы полей (`apps/news/lib/constants.php`)

```
NEWS_SLUG        min 3, max 60; зарезервированы: admin, c, t
title            min 3, max 120
lead             max 300
paragraphTitle   max 120
paragraphText    max 4000
paragraphs       не больше 40 абзацев
seoTitle         max 120
seoDescription   max 300
image (cover, ogImage)  max 300
oldSlugs         не больше 10 на материал
SEARCH_MAX_LENGTH 100
CATEGORY_FIELDS  title min 2 max 60, description max 300
TAG_FIELDS       label min 2 max 40, на материал не больше 10 тегов, сырой список max 600
```

Форма и серверная проверка читают одни и те же константы: литерал в разметке — находка стража.

### 8.2 Статусы и видимость

Статусы: `DRAFT`, `PUBLISHED`. Материал виден на сайте, если `status = PUBLISHED` и
`published_at <= now()` (`visibleWhere($now)` / `isOpen($item, $now)` в
`apps/news/lib/visibility.php`). `published_at` в будущем — расписание: материал не виден
на сайте, но виден в админке во вкладке «Ждут срока». Черновик виден только в админке и по
`?draft=1` для редактора.

### 8.3 Действия и уведомления

Кнопка решает, а не поле формы: `resolveStatus($intent, $current)`. Ключи уведомлений и их
русские тексты переносятся дословно.

`NEWS_NOTICE_TEXT`: `created`, `published`, `scheduled`, `updated`, `unpublished`, `pinned`,
`unpinned`, `unchanged`, `slugChanged`.
`CATALOG_NOTICE_TEXT`: `created`, `renamed`, `described`, `hidden`, `shown`, `moved`,
`deleted`, `topped`, `bottomed`, `tagRenamed`, `tagDeleted`.

Каждый ключ обязан иметь кнопку, которая его вызывает, и каждая кнопка — ключ в словаре
(страж «кнопка ↔ обработчик ↔ словарь»).

Правила действий:
- Черновик сохраняется всегда, в том числе без текста.
- Выход на печать (из формы и из кнопки списка) без разобранного текста запрещён одним
  общим правилом `publishTextError($status, $body)`.
- Отказ сохранения возвращает набранный текст в форму, а не пустые поля.
- Пустая правка возвращает `unchanged` и не сбрасывает кеш (в PHP кеша нет — правило
  сводится к тексту уведомления).
- Смена адреса запоминает прежний в `tbl_news_old_slug`; старый адрес отвечает постоянным
  редиректом (301) на новый, с `?draft=1`, если материал сейчас не виден.
- Закрепление: `pinned` поднимает материал первым в ленте, в рубрике и в теге; сводка
  админки показывает «закреплено N из M материалов» с русским склонением и не блокирует работу.
- Автор: при выходе на печать фиксируются `author_id` и снимок `author_email`, чтобы карточка
  читалась и после удаления аккаунта.
- Снятие с публикации сохраняет `published_at` (срок не сбрасывается).

### 8.4 Рубрики и теги

Рубрика: название уникально, адрес (`slug`) складывается из названия один раз транслитерацией
и дальше не меняется при переименовании; описание читается под заголовком страницы рубрики;
порядок задают кнопки «вверх»/«вниз»; скрытая рубрика не открывается, а её материалы уходят
из общей ленты; удалить можно только пустую рубрику, материалы при этом не удаляются —
проверка говорит об этом человеку.

Теги вручную не заводятся: их рождает форма материала (`resolveTagIds`). В справочнике тегов
только переименование (адрес тега не меняется) и удаление пустого тега.

### 8.5 Админка раздела

Вкладки: Сводка, Материалы, Рубрики, Теги. Сводка — панели со счётчиками (всего, черновики,
ждут срока, на сайте, закреплено из N). Список — вкладки состояний, поиск по заголовку
(доступен с первого ввода, даже когда список пуст), пагинация, кнопки строки
(«На печать» / «Снять с публикации» / «Закрепить» / «Снять закрепление»), каждая кнопка —
отдельная форма POST с намерением. Форма материала — все 14 полей, подсказка «Картинка
горизонтальная, 1200×630.» у обложки и OG-картинки, кнопка черновика первая в разметке
(случайный Enter сохраняет черновик, а не печатает), кнопка печати — вторая, но визуально
слева.

Все экраны работают без JavaScript: формы отправляются браузером, действия выполняются
на сервере.

### 8.6 Метаданные, карта сайта, OG

Карточка отдаёт `title`, `description`, `robots` (`noindex` по флагу материала), OG-теги
(`og:title`, `og:description`, `og:image`, `og:type=article`) и JSON-LD `NewsArticle`.
OG-картинка — 1200×630. `sitemap.xml` собирается из хука `sitemap_urls`: видимые материалы,
страницы рубрик и тегов; скрытые рубрики и материалы с `noindex` в карту не попадают.
`robots.txt` — из хука `robots_lines`, включает `Disallow` приватных путей из манифестов.

## 9. Почта

`core/mailer.php`: `Mailer::send(array $message): Result` — свой SMTP-клиент
(`stream_socket_client` с `tls://`, порт 587, STARTTLS, AUTH LOGIN, таймауты соединения и
команды, проверка кодов ответа). Настройки — в `config.php` (`SMTP_HOST`, `SMTP_PORT`,
`SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`), в репозитории только `config.sample.php`.
Перед отправкой — `apply_filters('before_mail_send', $message)`.
Функция `mail()` запрещена стражем.

В пилоте письма не отправляются: раздел «Новости» их не шлёт. Клиент делается сразу, потому
что рассылка ответов на заявки (свой план) подключится к нему без переделки; проверка —
на SMTP-заглушке в Docker.

## 10. Тесты и локальная разработка

### 10.1 Окружение

`docker-compose.dev.yml`: сервис `php` (`php:8.3-cli` + `pdo_mysql`, `mbstring`, `gd`,
`openssl`, `fileinfo`; `php -S 0.0.0.0:8080 -t public`), сервис `db` (`mysql:8.0`,
хост-порт **3307** — не пересекается с `english-portal-db-1` на 5433 и вторым проектом),
сервис `mailpit` (SMTP-заглушка). Базы: `cms_dev` и `cms_test`; тестовую сбрасывает
`scripts/db-reset` — правило «живую базу не сбрасываем» относится только к боевой.

### 10.2 Слои тестов

1. **Правила без базы** (`tests/unit/`): пределы полей, `slugify` и транслитерация,
   `visibleWhere`/`isOpen`, `resolveStatus`, `publishTextError`, `rememberOldSlug`, `plural`,
   словари уведомлений, `escapeLike`, `resolveTagIds` (на заглушке БД), генератор `id`.
2. **Стражи исходников** (`tests/guard/`): сканирование файлов регулярками — нет склеивания
   SQL и `$queryRaw`-аналогов, нет `mail()`, нет `echo $` без `e()` вне помеченных мест,
   `x-forwarded-for` не читается, каждый маршрут манифеста имеет обработчик, приватные пути
   закрыты в `robots.txt` и в шаблоне, пределы в форме берутся из `constants.php`,
   в `sql/` нет `DROP`/`TRUNCATE`/`DELETE FROM`, каждый ключ уведомления имеет кнопку.
3. **HTTP-проверки на тестовой базе** (`tests/http/`): поднимается `php -S`, база создаётся
   из `sql/`; проверяются лента, карточка, страницы рубрики и тега, 404, 301 со старого
   адреса, `sitemap.xml`, `robots.txt`, вход и выход, отказ анонима на `/news/admin`,
   отказ при чужом CSRF-токене, создание черновика, отказ печати без текста, публикация,
   снятие с публикации, закрепление, справочники рубрик и тегов, установка приложения
   кнопкой и отказ при `requiresCore` выше ядра.

Ворота перед коммитом: `php -l` по всем файлам, PHPStan (уровень 6), PHP-CS-Fixer,
PHPUnit — полный зелёный прогон, вывод без предупреждений.

## 11. Деплой

1. Проверка хостинга одноразовым зондом (удаляется сразу после): версия PHP ≥ 8.1;
   расширения `pdo_mysql`, `mbstring`, `gd`, `openssl`, `fileinfo`, `json`; Argon2id;
   `memory_limit`, `upload_max_filesize`, `post_max_size`; открыт ли исходящий порт 587;
   есть ли cron; переносится ли документ-корень на `public/`.
2. `scripts/deploy.sh`: SSH + `rsync` (не по одному файлу), исключая `tests/`, `composer.*`,
   `vendor/`, `.git/`, `docs/`; оба варианта раскладки (корень на `public/` или весь проект
   с защитным `.htaccess`).
3. На сервере создаётся `config.php` (права 600) из `config.sample.php`.
4. `setup.php` → администратор → `/admin/apps` → «Установить» для «Новостей».
5. Проверка на месте: журнал `tbl_app_migration` — две строки установки, `version = 1.0.0`,
   три стартовые рубрики, `/news` открывается, `/news/admin` закрыт для анонима и не
   индексируется, `sitemap.xml` и `robots.txt` отдают ожидаемое, HTTPS работает.
6. Домен и сертификат — средствами хостинга; `secure`-куки включаются по наличию HTTPS.

Пароли и значения `config.php` не попадают в репозиторий, в отчёты и в память; если команду
нужно выполнить с секретом, он извлекается в переменную внутри команды и не печатается.

## 12. Критерии готовности пилота

Пилот считается готовым, когда на локальном стенде и на виртуальном хостинге выполняются:

1. `setup.php` создаёт таблицы ядра и первого администратора, после `install.lock` отвечает 404.
2. `/admin/apps` показывает «Новости» как не установленные, кнопка «Установить» создаёт
   таблицы раздела, две строки журнала и `version = 1.0.0`, три стартовые рубрики на месте.
3. Отказ установки при `requiresCore` выше `CORE_VERSION` даёт человеческий текст, таблицы не создаются.
4. Повторная установка не дублирует строки журнала; «Обновить» появляется только когда
   `version` в базе ниже версии манифеста.
5. Аноним на `/news/admin/**` получает 403 или редирект на `/login`, страницы раздела несут `noindex`,
   `robots.txt` закрывает приватные пути.
6. Редактор входит, видит сводку со счётчиками и «закреплено N из M материалов».
7. Создание черновика без текста проходит; выход на печать без текста запрещён и в форме, и кнопкой списка.
8. Отказ сохранения (например, занятый адрес) возвращает набранный текст в форму.
9. Публикация делает материал видимым в ленте, на странице рубрики, на странице тега и в `sitemap.xml`.
10. Снятие с публикации убирает материал с сайта и сохраняет срок.
11. Закреплённый материал идёт первым в ленте и в рубрике.
12. Смена адреса даёт 301 со старого на новый; старый адрес запоминается, лимит 10 соблюдается.
13. Назначенный к публикации материал не виден на сайте до срока, виден во вкладке «Ждут срока».
14. Рубрика: переименование не меняет адрес, описание читается на её странице, скрытие убирает
    материалы из общей ленты, удаление непустой отказывает с понятным текстом, порядок меняется кнопками.
15. Тег: переименование сохраняет адрес, удаление тега с материалами отказывает, создать тег в справочнике нельзя.
16. Поиск в списке материалов работает с первого ввода, спецсимволы `%` и `_` ищутся как текст.
17. Все формы работают без JavaScript (проверка отключённым JS в браузере).
18. Адаптивность 360…1440 на всех экранах раздела.
19. Ворота качества: `php -l`, PHPStan 6, PHP-CS-Fixer и PHPUnit зелёные, вывод без шума.
20. На виртуальном хостинге те же проверки повторяются; письма не отправляются, но SMTP-клиент
    проходит проверку на заглушке в Docker.

## 13. Риски и открытые вопросы

| Риск | Что делаем |
|---|---|
| Хостинг не даёт перенести документ-корень на `public/` | Запасной вариант раскладки с защитным `.htaccess` заложен в `deploy.sh`; проверяется до первого деплоя |
| Нет Argon2id | Фолбэк на bcrypt в `core/auth.php`, проверка в зонде |
| Исходящий порт 587 закрыт | Письма — через их почтовый SMTP на 465/587 или через почтовый ящик домена; в пилоте не блокирует ничего |
| MySQL 5.7 вместо 8.0 | `JSON` есть и в 5.7, но `utf8mb4`-индексы короче 191 символа — длина `slug` 60 и `email` 190 подобраны с запасом; `CHECK` не используем |
| Лимит 1024 МБ на процесс | Сборки на сервере нет; тяжёлые операции (перенос данных) — только локально |
| Нет Node на сервере | CSS собран и лежит в репозитории |
| PHP-сессии на shared-хостинге чистятся | Срок жизни сессии — 8 часов, повторный вход не теряет данные (черновики пишутся в базу) |
| Перенос правил по памяти | Источник — `english-portal/src/apps/news` и его тесты, сверяемся с кодом |

## 14. Что после пилота

Порядок портирования (каждый раздел — своя спецификация и свой план): CMS-страницы из блоков
и конструктор (включая живые блоки новостей), личный кабинет и курсы с движком упражнений,
доска объявлений с модерацией, магазин с заказами, заявки и рассылка (подключается к
готовому SMTP-клиенту, нужен cron), перенос данных из PostgreSQL и переключение домена.

Задачи 18–21 Next.js-плана «Новости» остаются в силе и выполняются после пилота — по решению
человека портал пока не выключается.
