**Дата:** 2026-10-10
**Статус:** действующий документ проекта; сводит спецификацию 2026-10-06
(`2026-10-06-php-cms-pilot-design.md`), десять файлов планов (`docs/superpowers/plans/part1.md … part10.md`,
21 задача) и все решения, принятые за время задач 1–10.
**Что делать с этим документом:** читать как единое ТЗ. Спорные детали по-прежнему решаются по

**Не отменяет:** спецификацию 2026-10-06 (её разделы 1–3 подтверждены человеком) и планы частей 1–10.

## 1. Предмет и цель

Сделать CMS на PHP 8.3 и MySQL, которая целиком работает на виртуальном (shared) хостинге: без
долгоживущего процесса, без Docker на сервере, без Node на сервере, без рантайм-зависимостей.
Архитектура по образцу WordPress: ядро не правят, разделы живут в приложениях и подключаются через
точки расширения.

Пилот = ядро плюс одно приложение «Новости». Остальные разделы текущего портала (курсы и кабинет,
CMS-страницы из блоков, доска объявлений, магазин, заявки и рассылка) портируются после пилота,
каждый своей спецификацией и своим планом.

Причина смены стека: на виртуальном хостинге TimeWeb Node.js нельзя запускать как службу или
веб-сервер, поэтому Next.js дал бы только статический экспорт — без кабинета, админки, форм и
действий. PHP живёт от запроса до запроса и в ограничения хостинга попадает.

## 2. Границы

**В пилоте:** ядро (настройки, идентификаторы, даты, текст, PDO-слой, хуки, шаблоны и тема, запрос,
ответ, маршрутизатор, сессии, вход и права, CSRF, уведомления, помощники форм, реестр приложений,
миграции и журнал обновлений, установщик, настройки сайта, карта сайта и robots, SMTP-контур,
журнал ошибок, каркас админки), приложение «Новости» целиком (схема, правила, справочники, публичные
страницы, экраны админки, загрузка обложек, метаданные), выкладка на хостинг с зондом и приёмкой.

**Не в пилоте:** перенос данных из PostgreSQL (база стартует пустой), разделы портала кроме
«Новостей», конструктор страниц из блоков и живые блоки, очереди, кеш-слой, REST API, мультисайт,
переводы интерфейса, отправка писем (клиент делается сразу, писем в пилоте нет).

**Не отменено:** задачи 18–21 Next.js-плана «Новости» — портал остаётся на `main`, живая база в
состоянии «новости не установлены», возврат к ним после пилота по решению человека.

## 3. Платформа и ограничения среды

| Ограничение хостинга | Требование к проекту |
|---|---|
| Нет долгоживущего процесса | Каждый запрос обслуживает `public/index.php` и завершается; кеша в памяти между запросами нет ни у одного компонента |
| 1024 МБ на процесс | Никакой сборки на сервере; CSS собранный лежит в репозитории, зависимости только dev |
| Только MySQL 5.7/8.0 | Одна база, InnoDB, `utf8mb4` / `utf8mb4_unicode_ci`, префикс таблиц вместо схем |
| Нет Node | Tailwind собирается локально (`scripts/css`), в репозитории готовый `public/assets/app.css` |
| `mail()` ненадёжна | Свой SMTP-контур на `stream_socket_client`, порты 465/587, обязательное шифрование (раздел 8) |
| cron есть, но пилоту не нужен | Видимость по сроку вычисляется при запросе (`visibleWhere($now)`), фоновых задач нет |
| Документ-корень не всегда переносится | Два варианта раскладки в `scripts/deploy.sh`: `public` (корень перенесён) и `root` (вся структура + защитный `.htaccess`) |

Версии: целевая PHP 8.3, минимально поддерживаемая 8.1. Синтаксис 8.4 (`array_find`, asymmetric
visibility, `new` в цепочке без скобок) запрещён. В каждом PHP-файле первая строка после `<?php` —
`declare(strict_types=1);`. Стиль близок к PSR-12, вычитается PHP-CS-Fixer.

Требуемые расширения: `pdo_mysql`, `mbstring`, `gd`, `openssl`, `fileinfo`, `json`. Проверяются
зондом до первого деплоя (раздел 13).

## 4. Архитектура

### 4.1 Каталоги

```
cms/
  public/        заливается на хостинг: index.php, setup.php, .htaccess, assets/, uploads/
  core/          ядро: bootstrap, config-loader, version, hooks, escape, id, date, text, db,
                 request, response, ResponseFinished, router, routes, session, template, notice,
                 csrf, form, auth, options, apps, migrations, MigrationPlan, Mailer, SmtpSocket,
                 seo, log, storage/, templates/
  admin/         каркас админки: layout.php (шапка, вкладки из adminNav, уведомления)
  theme/         наша вёрстка: layout, login, home, 404, 403, partials (header, footer, cat), news/
  apps/<id>/     приложение: manifest.php, routes.php, admin.php, actions/, lib/, templates/, sql/, seed.php
  sql/           миграции ядра (0001_core_baseline.sql)
  tests/         bootstrap.php, TestDb.php, unit/, db/, guard/, http/, fixtures/
  scripts/       gate.sh, css, db-reset, deploy.sh, hosting-probe.php, make-og-default.php,
                 responsive-check.mjs
  config.sample.php  образец настроек (в репозитории)
  config.php         боевые настройки (вне репозитория, права 600)
  composer.json      только require-dev: phpunit, phpstan, php-cs-fixer
```

`public/` — единственное, что видит веб-сервер. `config.php`, `core/`, `apps/`, `sql/`, `tests/`
лежат выше документ-корня; если хостинг не даёт перенести корень, структура кладётся целиком и
служебные каталоги закрывает корневой `.htaccess` (`Require all denied` до правил
переписывания — порядок важен, иначе запрос к существующему исходнику пройдёт условием `!-f`).

### 4.2 Путь запроса

1. `public/index.php` читает `config.php`, подключает `core/bootstrap.php`.
2. `bootstrap.php`: PSR-4-автозагрузчик `Cms\Core\ → core/`, явочный список функциональных
   библиотек, часовой пояс, обработчики ошибок и исключений, хуки.
3. Старт сессии с безопасными флагами cookie.
4. `core/apps.php` читает манифесты включённых приложений и собирает таблицу маршрутов;
   порядок — ядро, затем приложения по алфавиту `id`.
5. `core/router.php` сопоставляет `REQUEST_URI` с маршрутами, извлекает параметры.
6. Гейты: приложение установлено и включено → путь не приватный для анонима → есть право.
7. `doAction('before_route', $match)`.
8. Действие: GET — контроллер, POST — обработчик из `actions/`.
9. `render('news/single', $data)` выбирает шаблон по иерархии, оборачивает в layout.
10. `doAction('after_route')`, вывод.

Несовпадение маршрута — `theme/404.php` со статусом 404 (причина отказа ядра печатается через
`e()`). Исключение — страница 500 (`core/templates/error.php`) с записью в
`core/storage/errors.log`, наружу только «что-то сломалось», без дампа стека и с
`Cache-Control: no-store`. Приложение, которого нет в реестре, — отдельный экран
`core/templates/not-installed.php`.

### 4.3 Маршруты

Ядро (регистрация в `core/routes.php`):

| Адрес | Метод | Доступ |
|---|---|---|
| `/` | GET | все |
| `/login` | GET, POST | все |
| `/logout` | POST | вошедшие |
| `/admin` | GET | `private`, право `login` |
| `/admin/apps` | GET, POST | `private`, право `manage` |
| `/sitemap.xml`, `/robots.txt` | GET | все |
| `*` | — | 404 |

«Новости»: `/news`, `/news/{slug}`, `/news/c/{slug}`, `/news/t/{slug}`, `/news/admin`,
`/news/admin/items`, `/news/admin/items/new`, `/news/admin/items/{id}`,
`/news/admin/categories`, `/news/admin/tags`. Служебные сегменты `admin`, `c`, `t` зарезервированы:
адрес материала не может их занимать — проверка в `validators.php` и в тесте.

### 4.4 Хуки

`core/hooks.php`: `addAction(string $hook, callable $fn, int $priority = 10)`, `addFilter(...)`,
`doAction(string $hook, ...$args)`, `applyFilters(string $hook, $value, ...$args)` (фильтр обязан
вернуть значение). Порядок — по возрастанию приоритета, одна точка регистрируется несколько раз.
Имена точек — snake_case, функции проекта — camelCase (отступление 1 раздела 11).

Действующие точки ядра: `before_route`, `after_route`, `page_head`, `page_footer`, `admin_nav`,
`sitemap_urls`, `robots_lines`, `notice_text`, `before_mail_send`, `app_installed`, `app_updated`.
Точка `form_field_error` из спецификации §5.4 в пилот не входит: тексты ошибок полей задаёт
`core/form.php` (`fieldError()`, `formError()`), потребителя у точки нет, а пустая регистрация —
это обещание, которое никто не проверяет.

### 4.5 Манифест приложения

`apps/news/manifest.php` возвращает массив: `id`, `title`, `version` (`1.0.0`), `requiresCore`
(`1.1.0`), `privatePaths` (`['/news/admin']`), `sql`, `adminNav`, `seed`.
`core/version.php` несёт `CORE_VERSION = '1.1.0'`. Приложение устанавливается только если
`requiresCore <= CORE_VERSION`; иначе — человеческий текст «нужна версия ядра не ниже X, в сборке Y».
`appManifests()` дополнительно читает каталог из `config.php` (`EXTRA_APPS_DIR`, по умолчанию пусто):
на fixture-приложениях `demo` и `future` проверяются «Установить», «Обновить» и отказ установки.
На сервере ключ не заполняется.

### 4.6 Шаблоны, тема, статика

`render(string $template, array $data = [])` берёт первый найденный:
`apps/<приложение>/templates/<имя>.php` → `theme/<приложение>/<имя>.php` →
`core/templates/<имя>.php` → `theme/404.php`. Частичные шаблоны — `partial(...)`.
Layout — `theme/layout.php` с `$title`, `$description`, `$content`, `$head` (OG, robots).

Весь вывод — через `e()` (`htmlspecialchars`, `ENT_QUOTES | ENT_SUBSTITUTE`, UTF-8). Страж
`OutputEscapingTest` запрещает в шаблонах `echo $` и `<?=` без `e(`, кроме мест, помеченных
`/* @safe html */` (разметка абзацев с `**выделением**`).

Дизайн-система, кот-талисман, цвета, шрифты и адаптивность переносятся из `english-portal` как есть.
Tailwind собирается локально; шаг свежести артефакта стоит в воротах первым (раздел 10). В разметке
классы читаются из `@source`-путей сборки, а не из прозы планов; мёртвые правила CSS ловит страж
`StyleSourceTest`, вес ассетов — `AssetWeightTest`.

## 5. Данные

### 5.1 Правила

- Одна база MySQL, InnoDB, `utf8mb4` / `utf8mb4_unicode_ci`. Каждое `CREATE TABLE` в `sql/` —
  с явным `DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci` (серверный default 8-го MySQL —
  `utf8mb4_0900_ai_ci`, которого 5.7 не знает).
- Префикс таблиц из `config.php` (по умолчанию `tbl_`), в запросах имя только через `t('news_item')`.
- Идентификаторы строк контента — `VARCHAR(26)` из `core/id.php`: 26 символов, первые 10 — время в
  base32, дальше случайные; сортируемость по времени нужна для переноса из PostgreSQL, где
  `AUTO_INCREMENT` при восстановлении из дампа порядка не гарантирует. Исключение:
  `tbl_app_installation.id` = `id` приложения из манифеста, длина 32.
- Даты в базе — `DATETIME` в UTC; перевод в `Europe/Moscow` и русский вывод дат живут только в
  `core/date.php`. Вне этого файла запрещены `date(`, `->format(`, `strtotime(`, `new DateTime`
  (страж `DateUsageTest`). Исключение зафиксировано явно: `PHP_EOL` в `scripts/` разрешён,
  расширение стража на скрипты принимает только человек.
- Булевы — `TINYINT(1)`. Перечисления — `VARCHAR` со справочником значений в PHP: `CHECK` в
  MySQL 5.7 молча игнорируется, поэтому правило живёт в коде и сторожится тестом.
- Миграции только дополняющие: в каталогах `sql/` нет `DROP`, `TRUNCATE`, `DELETE FROM`,
  `ALTER … DROP COLUMN` (страж `SqlSafetyTest`); файлы приложений пишутся через
  `CREATE TABLE IF NOT EXISTS`.
- Никакого склеивания строк в SQL: только плейсхолдеры `?` или `:name`; запрещены `PDO::query`,
  `PDO::exec`, `mysqli_*`. Подстроковый поиск — через `escapeLike()` (экранирует `\`, `%`, `_`).
- Слой доступа: `db()`, `t()`, `all()`, `one()`, `value()`, `run()`, `tx()`, `escapeLike()`.
- Настройки «плывущего» состояния — в `tbl_option` (`getOption()` / `setOption()`, запись — одна
  пишущая инструкция `INSERT … ON DUPLICATE KEY UPDATE`, а не «проверил, потом записал»).

### 5.2 Таблицы пилота

Ядро (`sql/0001_core_baseline.sql`): `tbl_user` (id, email UNIQUE, password_hash, name, role,
session_version, blocked_at, created_at), `tbl_login_attempt` (BIGINT AUTO_INCREMENT, email, ip,
attempted_at, индексы `(email, attempted_at)` и `(ip, attempted_at)`), `tbl_option`
(option_name PK, option_value TEXT NULL, autoload), `tbl_app_installation` (id VARCHAR(32) PK,
enabled, installed_at, version), `tbl_app_migration` (id VARCHAR(26) PK, app, name, checksum
CHAR(64), applied_at, UNIQUE `(app, name)`).

Раздел «Новости» (два файла `apps/news/sql/`): `tbl_news_category` (slug UNIQUE, title UNIQUE,
description, order_index, visible), `tbl_news_tag` (slug UNIQUE, label UNIQUE), `tbl_news_item`
(slug UNIQUE, title, lead, cover, category_id FK `ON DELETE RESTRICT`, body JSON NULL, status,
published_at, pinned, seo_title, seo_description, og_image, noindex, author_id, author_email,
created_at, updated_at; индексы `(status, published_at)`, `(category_id, status, published_at)`,
`(pinned, published_at)`), `tbl_news_item_tag` (PK `(item_id, tag_id)`, оба FK `ON DELETE CASCADE`,
индекс `(tag_id, item_id)`), `tbl_news_old_slug` (slug PK, item_id FK CASCADE, created_at).

`tbl_news_old_slug` заменяет `String[] oldSlugs` из PostgreSQL: поиск по JSON-массиву в MySQL без
индекса — сканирование таблицы на каждом открытии старого адреса. Лимит «не больше 10 на материал»
проверяет `rememberOldSlug()` в PHP.

`body` — JSON-массив абзацев `[{title, text}]`; сырого HTML в материале нет, выделение задаётся
`**звёздочками**` и разбирается при выводе. Валидность JSON проверяет PHP перед записью.

### 5.3 Установка, обновление, экран «Приложения»

`public/setup.php` (одноразовый): проверяет версию PHP и расширения, создаёт таблицы ядра, спрашивает
имя сайта, email и пароль администратора, пишет `tbl_option` и `tbl_user` с ролью `admin`, создаёт
`public/install.lock`. После появления замка скрипт отвечает 404; проверка замка — одна точка
(`setupLocked()`), отказ по неизвестному адресу считает хеш пароля, а не отвечает сразу (иначе по
времени ответа различаются существующий и несуществующий email).

`core/migrations.php`: `planApp(string $app): MigrationPlan` — список ещё не применённых файлов из
`sql/` приложения плюс сверка sha256 уже применённых; `applyApp()` применяет файлы по порядку и
пишет строку журнала сразу после каждого файла, затем один раз поднимает
`tbl_app_installation.version` и вызывает `doAction('app_updated')`. Изменившийся применённый файл —
отказ «файл миграции X изменён после применения», а не тихая перезапись. Любая DDL-команда в MySQL
вызывает неявный коммит, поэтому «одна транзакция на весь план» была бы невыполнимым обещанием
(отступление 9 раздела 11); повторный запуск продолжает с непройденного файла.

Первая установка дополнительно запускает `seed.php` приложения: у «Новостей» он создаёт три стартовые
рубрики, только добавляет строки и идемпотентен по уникальному `slug`.

`/admin/apps` показывает состояния (не установлено / установлено / требует обновления / выключено),
версию в базе против версии манифеста и кнопки «Установить», «Обновить», «Выключить», «Включить».
«Обновить» появляется только когда `version` в базе ниже версии манифеста.

## 6. Безопасность

- Сессия: `session.cookie_httponly = 1`, `cookie_samesite = 'Lax'`, `cookie_secure` при HTTPS,
  `use_strict_mode = 1`, срок жизни 8 часов. Отзыв сессий — увеличением `session_version`
  пользователя; `currentUser()` сверяет версию на каждый запрос.
- Пароли: `password_hash(PASSWORD_ARGON2ID)`, при отсутствии расширения — `PASSWORD_BCRYPT`
  (в official-образе `php:8.3-cli` Argon2id может не быть); проверка `password_verify` +
  `password_needs_rehash`. Наличие Argon2id на хостинге проверяет зонд.
- Роли пилота: `admin` (всё) и `editor` (разделы контента). Право проверяет `getEditorAccess()`:
  аноним или заблокированный получает редирект на `/login`, а на приватном пути админки раздела —
  403 страницей темы (`theme/403.php`) без содержимого.
- Брутфорс: не больше 5 неудачных попыток на email за 15 минут и 20 на IP за час; попытки пишутся в
  `tbl_login_attempt`. IP берётся только из `REMOTE_ADDR`; `x-forwarded-for`, `x-real-ip`,
  `client-ip` не читаются нигде (страж `ClientIpTest`).
- Открытый редирект: параметр `?next=` после входа принимается только если это внутренний путь
  того же сайта; чужой адрес — отказ.
- CSRF: токен в сессии, скрытое поле `_token` в каждой форме, проверка в каждом POST-обработчике;
  несовпадение — 403 и запись в журнал. Покрытие проверяет страж `CsrfCoverageTest` (он видит все
  формы файла и измеряет границы регистронезависимо).
- Формы: `method="post"` везде, где есть пароль или изменение данных; намерение кнопки — отдельное
  поле `intent` или `op`; после успеха — PRG-редирект с `?notice=<ключ>`. Каждый экран работает без
  JavaScript.
- Загрузки: `public/uploads/images/<сгенерированное-имя>.<расширение>`; MIME по содержимому (`finfo`),
  размер ≤ 5 МБ, расширения `jpg, jpeg, png, webp`; путь из формы не используется. Каталог загрузок
  разведён по типу содержимого: картинки в `images`, прочие файлы в `files`, барьер исполнения один
  на дереве — `public/uploads/.htaccess`.
- Заголовки ответа (`public/.htaccess` и дубль в `bootstrap.php`, потому что не каждый хостинг даёт
  `mod_headers`): `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`,
  `X-Frame-Options: SAMEORIGIN`, `Content-Security-Policy` из текущего проекта.
- Приватные экраны (админка, вход, 500, 403) сами отдают `Cache-Control: no-store` и несут
  `<meta name="robots" content="noindex, nofollow">`; приватные пути из манифестов попадают в
  `robots.txt` как `Disallow` (страж `PrivatePathsRobotsTest`).
- Служебные файлы недоступны по HTTP: `setup.php`, `config.php`, `sql/`, `tests/`, `core/`, `apps/`
  (страж `WebServerConfigTest`; при выкладке проверяется кодом ответа — 403 или 404, но не 200).
- Журнал ошибок `core/storage/errors.log` лежит вне web-корня; в него не пишутся пароли, токены и
  содержимое писем. Имя хоста и порт почтового сервера писать можно и нужно: без них отказ отправки
  неотличим от неверной настройки.
- Зоны нажатия: любой интерактивный элемент ≥ 44 px (`min-h-[44px]`, у ссылок и кнопок — в связке с
  `inline-flex … items-center`) — на полях и кнопках форм, в ссылках шапки, во вкладках админки.
  Исключения «текстовая ссылка может быть мельче» в проекте нет; измеряет страж `TapTargetTest`,
  читая классы, а не подстроки.

## 7. Раздел «Новости»

Правила переносятся из `english-portal/src/apps/news` без изменений; источник истины — TS-файл,
названный в задаче, и его тесты, а не память.

**Пределы полей** (`apps/news/lib/constants.php`, форма и сервер читают одни и те же константы;
литерал предела в шаблоне — находка стража): slug 3…60, зарезервированы `admin`, `c`, `t`;
title 3…120; lead ≤300; заголовок абзаца ≤120; текст абзаца ≤4000; абзацев ≤40; seo title ≤120;
seo description ≤300; путь картинки ≤300; прежних адресов ≤10; поиск ≤100 символов; рубрика —
title 2…60, description ≤300; тег — label 2…40, на материал ≤10 тегов, сырой список ≤600.

**Статусы и видимость.** `DRAFT`, `PUBLISHED`. Материал виден, если `status = PUBLISHED` и
`published_at <= now()` (`visibleWhere($now)` / `isOpen($item, $now)`). `published_at` в будущем —
расписание: на сайте не виден, в админке виден во вкладке «Ждут срока». Черновик виден только в
админке и по `?draft=1` редактору.

**Действия и уведомления.** Кнопка решает, а не поле формы: `resolveStatus($intent, $current)`.
Ключи `NEWS_NOTICE_TEXT`: `created`, `published`, `scheduled`, `updated`, `unpublished`, `pinned`,
`unpinned`, `unchanged`, `slugChanged`. Ключи `CATALOG_NOTICE_TEXT`: `created`, `renamed`,
`described`, `hidden`, `shown`, `moved`, `deleted`, `topped`, `bottomed`, `tagRenamed`, `tagDeleted`.
Русские тексты переносятся дословно. Каждый ключ обязан иметь кнопку, которая его вызывает, и каждая
кнопка — ключ в словаре (страж `NoticeKeyTest`).

Правила: черновик сохраняется всегда, в том числе без текста; выход на печать без разобранного текста
запрещён одним общим правилом `publishTextError($status, $body)` и в форме, и кнопкой списка; отказ
сохранения возвращает набранный текст в форму, а не пустые поля; пустая правка даёт `unchanged`;
смена адреса запоминает прежний и отвечает с него 301 на новый (с `?draft=1`, если материал сейчас
не виден); закрепление поднимает материал первым в ленте, в рубрике и в теге, сводка показывает
«закреплено N из M материалов» с русским склонением; при выходе на печать фиксируются `author_id` и
снимок `author_email`, чтобы карточка читалась после удаления аккаунта; снятие с публикации
сохраняет `published_at`.

**Рубрики.** Название уникально; адрес складывается из названия один раз транслитерацией и при
переименовании не меняется; описание читается под заголовком страницы рубрики; порядок задают кнопки
«вверх»/«вниз»; скрытая рубрика не открывается, а её материалы уходят из общей ленты; удалить можно
только пустую рубрику, материалы при этом не удаляются — проверка говорит об этом человеку.

**Теги.** Вручную не заводятся: их рождает форма материала (`resolveTagIds`). В справочнике
доступны только переименование (адрес не меняется) и удаление пустого тега.

**Экраны админки раздела.** Вкладки: Сводка, Материалы, Рубрики, Теги. Сводка — панели со счётчиками
(всего, черновики, ждут срока, на сайте, закреплено из N). Список — вкладки состояний, поиск по
заголовку доступен с первого ввода даже на пустом списке, спецсимволы `%` и `_` ищутся как текст,
пагинация, кнопки строки («На печать», «Снять с публикации», «Закрепить», «Снять закрепление») —
каждая отдельной формой POST с намерением. Форма материала — все 14 полей, подсказка «Картинка
горизонтальная, 1200×630.» у обложки и OG-картинки, кнопка черновика первая в разметке (случайный
Enter сохраняет черновик, а не печатает), кнопка печати вторая, но визуально слева.

**Метаданные, карта сайта, OG.** Карточка отдаёт `title`, `description`, `robots` (`noindex` по флагу
материала), OG-теги (`og:title`, `og:description`, `og:image`, `og:type=article`) и JSON-LD
`NewsArticle`. OG-картинка 1200×630, фирменная заглушка — `public/assets/img/brand/og-default.png`.
`/sitemap.xml` собирается из хука `sitemap_urls` (видимые материалы и страницы рубрик; скрытые
рубрики, материалы с `noindex` и подборки тегов — они несут `noindex, nofollow` — в карту не
попадают) и считается заново на каждый вызов — кеша процесса нет. `/robots.txt` — из хука `robots_lines` плюс приватные пути манифестов.

## 8. Почта

В пилоте письма не отправляются: раздел «Новости» их не шлёт. Контур делается сразу, чтобы рассылка
ответов на заявки подключилась к нему без переделки.

`Cms\Core\Mailer::send(array $message): Result` собирает письмо (заголовки через тот же
`headerText()`, что и тема; `Bcc` в конверт не попадает, в текст письма не печатается) и вызывает
`applyFilters('before_mail_send', $message)` перед отправкой. `Cms\Core\SmtpSocket` — разговор по
сокету.

Требования к каналу (приняты как обязательные, проверены фикс-раундами задачи 10):

- Порт 465 — соединение сразу идёт через `ssl://`.
- Порт 587 — без успешного `STARTTLS` отправка запрещена: отказ выносится до `AUTH`, до записи в
  журнал и до `deliver()`. Сервер, который не объявил `STARTTLS` на порту отправки, не получает
  письма.
- Маска рукопожатия — только TLS 1.2 и TLS 1.3 (`STREAM_CRYPTO_METHOD_TLSv1_2_CLIENT |
  STREAM_CRYPTO_METHOD_TLSv1_3_CLIENT`); рукопожатие, не подтверждённое повторным `EHLO`, — отказ.
- Правила проверки сертификата задаются контекстом потока до соединения (`verify_peer`,
  `verify_peer_name`, `peer_name`, `SNI_enabled`, `SNI_server_name`) и потому действуют и на
  `ssl://`, и на переход по `STARTTLS` (отдельного контекста он не принимает). Ключа `local_name`
  у контекста `ssl` в PHP 8.3 нет — требование «сертификат должен соответствовать имени хоста»
  исполняет `peer_name`.
- `AUTH LOGIN` — только по зашифрованному каналу. Зашифрованный канал — факт успешного соединения,
  а не значение настройки.
- Порт 25 (курьерское реле) и 1025 (dev-приёмник) работают без шифрования, но незакрытый канал
  обязан остаться в журнале: `logWarn('mail.plaintext', ['host' => …, 'port' => …])`. В журнал и в
  тексты отказов не попадают содержимое письма, логин и пароль; в шагах `AUTH` строка ответа сервера
  в отказ не попадает (сервер мог бы вернуть в неё наши же данные), остаётся только код.
- Возможность сервера ищется по началу строки ответа EHLO (`/^250[- ]ИМЯ(\s|$)/mi`), а не подстрокой:
  упоминание чужого слова в баннере не должно объявлять команду.
- Многострочный ответ дочитывается до последней строки; код `4xx`/`5xx` в середине — не успех.
- Точка в начале строки удваивается по RFC 5321 §4.5.2, внутри строки не трогается. Длина записи
  сверяется с длиной запроса: «недописанный» запрос не считается целым.
- Настройки — `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` в `config.php`;
  в репозитории только `config.sample.php`.
- `mail()` и `mb_send_mail()` запрещены во всём проекте, вместе с обходными формами:
  `call_user_func('mail'|'mb_send_mail', …)`, присвоением имени почтовой функции переменной
  (`$send = 'mail'`), `eval`/`create_function`, а также именами сторонних почтовых библиотек
  (`PHPMailer`, `Symfony\…\Mailer`) — рантайм-зависимостей у ядра нет. Проверяет страж
  `MailFunctionTest`, который обязан находить равноправные формы нарушения и не находить русский
  текст вида `e-mail (…)`.
- Проверка контура: юнит-набор с подставным SMTP-сервером (клиент живёт в дочернем процессе,
  сервером и судьёй остаётся тест; пароль приходит дочернему процессу по стандартному потоку ввода,
  не аргументом командной строки) и HTTP-интеграция на `mailpit` (8025/1025), которая обязана
  исполняться в воротах, а не пропускаться молча.
- Обязательность шифрования на 587 против настоящего сервера хостинга в локальных наборах
  недоказуема: `mailpit` STARTTLS не реализует, а доверие локальному сертификату потребовало бы
  ключ `cafile`, которого в проекте нет. Эта проверка — пункт чек-листа выкладки (раздел 13).

## 10. Тесты и ворота качества

### 10.1 Окружение

`docker-compose.dev.yml`: сервис `php` (`php:8.3-cli` + `pdo_mysql`, `mbstring`, `gd`, `openssl`,
`fileinfo`, `procps`; `php -S 0.0.0.0:8080 -t public`), сервис `db` (`mysql:8.0`, порт хоста
**3307** — не пересекается с базами других проектов), сервис `mailpit`. Базы `cms_dev` и `cms_test`
создаёт `docker/mysql-init.sql` с явным `utf8mb4_unicode_ci`; в dev-контейне у MySQL пустой пароль
(правило «пароль не попадает в репозиторий» важнее удобства, база доступна только с `localhost`).
Тестовую базу пересоздаёт `scripts/db-reset` — и только её; правило «живую базу не сбрасываем»
относится к боевой базе и к базе `english-portal`.

Все команды выполняются в каталоге `cms/` и только внутри контейнера, всегда с `-T`:
`docker compose -f docker-compose.dev.yml run --rm -T php vendor/bin/phpunit …`.

### 10.2 Слои тестов (четыре набора)

1. `tests/unit/` — правила без базы: пределы полей, `slugify` и транслитерация,
   `visibleWhere`/`isOpen`, `resolveStatus`, `publishTextError`, `rememberOldSlug`, `plural`,
   словари уведомлений, `escapeLike`, генератор `id`, даты, хуки, шаблонизатор, запрос,
   настройки, журнал, `Mailer` и `SmtpSocket`.
2. `tests/db/` — то, чему нужна база, но не нужен веб-сервер: схема ядра, PDO-слой, префикс таблиц,
   реестр приложений, миграции и их отказы, настройки-опции, сессии и отзыв, лимиты входа, CSRF.
   (Спецификация §10.2 делила тесты на три слоя; четвёртый набор — отступление 8.)
3. `tests/guard/` — стражи исходников: сканирование файлов (лексером там, где регулярка врёт).
   Действуют: `SqlSafetyTest`, `MailFunctionTest`, `OutputEscapingTest`, `ClientIpTest`,
   `DateUsageTest`, `RouteHandlersTest`, `PrivatePathsRobotsTest`, `CsrfCoverageTest`,
   `NoticeKeyTest`, `TapTargetTest`, `StyleSourceTest`, `AssetWeightTest`, `WebServerConfigTest`.
   Страж обязан проверять собственную силу: равноправные формы нарушения находятся, текстовые
   совпадения — не находятся.
4. `tests/http/` — HTTP на тестовой базе: поднимается `php -S` (`tests/http/Kernel.php`), ходит
   curl-ом; проверяются лента, карточка, рубрика и тег, 404, 301 со старого адреса, `sitemap.xml`,
   `robots.txt`, вход и выход, отказ анонима на `/news/admin`, отказ при чужом CSRF-токене,
   создание черновика, отказ печати без текста, публикация, снятие, закрепка, справочники,
   установка приложения кнопкой и отказ при `requiresCore` выше ядра, экраны 403/500/503-состояния,
   SMTP-интеграция на `mailpit`.

Наборы изолированы: переменные окружения подставляются только к ключам, которые уже есть в
`config.sample.php`, а `config()` кеширует настройки на процесс — порядок файлов не должен влиять на
чужие проверки. Пропуск в воротах — это явный `markTestSkipped` с текстом-фактом, и их число в
воротах известно (после задачи 10 — ровно один).

### 10.3 Ворота

Перед каждым коммитом — `bash scripts/gate.sh`, единственный разрешённый прогон:

1. свежесть собранной статики (Tailwind собирается во временный каталог и сравнивается побайтово с
   `public/assets/app.css`; нет `node_modules/.bin/tailwindcss` — ворота красные с подсказкой
   `npm ci`, а не закомментированная строка);
2. `php -l` по всем PHP-файлам (статус доходит до ворот, пустой список файлов — падение, а не «ноль
   файлов проверено и зелёные»);
3. PHPStan уровень 6;
4. PHP-CS-Fixer `--dry-run --diff`;
5. PHPUnit полным прогоном (все четыре набора), зелёный, вывод без предупреждений.

Аргументы воротам не пробрасываются нарочно: с `"$@"` вызов вида `gate.sh --filter Что-то` гонял бы
четверть набора, а phpstan и фиксер зеленели бы, и коммит выглядел бы проверенным полным прогоном.
Ворота не имеют переключателя силы.

Единственная разрешённая реплика в выводе — подсказка PHP-CS-Fixer о том, что образ PHP 8.3 новее
минимума проекта 8.1 (печатается безусловно, снимается только понижением рабочей версии, а понижать
нельзя: PHPUnit 11 требует PHP ≥ 8.2). Всё остальное — находка.

**Категорический запрет:** ворота не ослабляются. Никаких `@phpstan-ignore`, понижения уровня
`phpstan.neon`, `--no-verify`, удаления, смягчения или перевода существующей проверки в пропуск.
Падает анализатор или фиксер — правится код (или текст плана), а не настройки проверки. Файлы
`scripts/gate.sh`, `phpunit.xml`, `.php-cs-fixer.dist.php`, `phpstan.neon`, `docker-compose.dev.yml`,
`config.sample.php`, `core/bootstrap.php` в рабочий день не трогаются; если задача требует их правки,
это отдельное решение человека.

## 11. Отступления от спецификации 2026-10-06 (осознанные)

1. Имена функций — camelCase (`visibleWhere`, `addRoute`, `escapeLike`, `nowUtc`), имена хуков —
   snake_case (их задаёт спецификация §5.4 и видно в шаблонах).
2. Функциональные библиотеки подключаются явным списком, классы (`Cms\Core\Mailer`,
   `Cms\Core\SmtpSocket`, `Cms\Core\MigrationPlan`) — PSR-4-автозагрузкой; функции PHP не автозагружаются.
3. Argon2id выбирается по наличию поддержки, фолбэк — bcrypt; обе ветки покрыты тестом, хостинг
   проверяется зондом.
4. «Обновить» и отказ установки проверяются на fixture-приложениях (`demo`, `future`) через
   `EXTRA_APPS_DIR`, а не на «Новостях»: оба SQL-файла раздела применяются при первой установке, и
   незаписанных релизов на нём не остаётся.
5. В dev-контейне у MySQL пустой пароль; боевой `config.php` создаётся на сервере вручную.
6. Блочные функции чтения новостей (`blockNews`, `blockSingle`, `publishedBlockOptions`, `parseTags`,
   `categoryBlockOptions`, `tagBlockOptions`, `toBlock`) не портируются: конструктора страниц в пилоте нет.
7. `tbl_app_installation.id` — `VARCHAR(32)`, равен `id` приложения из манифеста.
8. Четыре набора тестов вместо трёх: добавлен `tests/db/`.
9. Обновление приложения — не одна транзакция, а запись в журнал после каждого применённого файла
   (DDL в MySQL коммитится неявно); файлы пишутся через `CREATE TABLE IF NOT EXISTS`.
10. PHPStan 2.x вместо 1.12 (уровень 6 тот же; у 1.12 печатается неподавляемый баннер, а «вывод ворот
    без предупреждений» — общее ограничение).
11. `.gitattributes` с `* text=auto eol=lf`: без него клон при `core.autocrlf=true` выкладывает CRLF,
    и у `scripts/gate.sh` ломается shebang, а `.htaccess` уходит на хостинг с лишними `\r`.
12. Обе dev-базы создаются с явным `utf8mb4_unicode_ci`; каждый `CREATE TABLE` — с явным
    `DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci`.
13. `composer.lock` в репозитории: держит версии инструментов одинаковыми на всех 21 задаче.
14. Одно предупреждение PHP-CS-Fixer в воротах разрешено (пункт 10 раздела 10.3).
15. Уточнение по почте (принято фикс-раундом задачи 10 вместо формулировки спецификации §9):
    клиент требует шифрования на порту 587, проверяет сертификат и имя хоста, ограничивает
    рукопожатие TLS 1.2/1.3, а незакрытый канал на 25/1025 записывает в журнал. Спецификация
    требовала «порт 587, STARTTLS» без отказа при его отсутствии.
16. Точка `form_field_error` из перечня хуков спецификации §5.4 в пилоте отсутствует (см. раздел 4.4).

## 13. Деплой и приёмка на хостинге

1. **Зонд** (`scripts/hosting-probe.php`, одноразовый, удаляется сразу после проверки): версия
   PHP ≥ 8.1; расширения `pdo_mysql`, `mbstring`, `gd`, `openssl`, `fileinfo`, `json`; Argon2id;
   `memory_limit`, `upload_max_filesize`, `post_max_size`; открыт ли исходящий порт 587; есть ли
   cron; переносится ли документ-корень на `public/`.
2. **Выкладка** (`scripts/deploy.sh`): SSH + `rsync` одной передачей (не по одному файлу), с
   исключениями `tests/`, `composer.*`, `vendor/`, `.git/`, `docs/`. `--delete` обязан идти вместе с
   исключениями `config.php`, `public/install.lock`, `public/uploads`, `core/storage` — их случайную
   потерю будет ловить страж `DeploySafetyTest` (создаётся задачей 21, его отсутствие до задачи 21 —
   известный долг, а не закрытая проверка). Режим `public` или `root` выбирается флагом; набор файлов
   одинаковый, потому что `public/index.php` требует `../core/bootstrap.php`. Проверка раскладки
   идёт после заливки.
3. На сервере создаётся `config.php` (права 600) из `config.sample.php`, значения — свои.
4. `setup.php` → первый администратор → `/admin/apps` → «Установить» для «Новостей» →
   `install.lock` на месте, установщик больше не отвечает.
5. **Проверка на месте:** журнал `tbl_app_migration` — две строки установки, `version = 1.0.0`,
   три стартовые рубрики; `/news` открывается; `/news/admin` закрыт для анонима и не индексируется;
   `sitemap.xml` и `robots.txt` отдают ожидаемое; ни один служебный файл не отдаётся (403 или 404, но
   не 200); HTTPS работает, `secure`-куки включены по наличию HTTPS; адаптивность 360…1440
   (`scripts/responsive-check.mjs` через Playwright) на всех экранах; зоны нажатия ≥ 44 px.
6. **Почта (единственная проверка, которую нельзя сделать локально):** отправка через настоящий
   сервер хостинга на 465 или 587 — с корректной цепочкой сертификатов и с проверкой, что при
   несовпадении имени или отсутствии `STARTTLS` письмо не уходит. Обязательность шифрования и
   проверка сертификата в локальных наборах доказуемы только как стражи регресса (в контейнере
   TLS 1.0 запрещён самой OpenSSL, а самоподписанный сертификат отвергается и по умолчанию).
7. Домен и сертификат — средствами хостинга.

## 14. Критерии готовности пилота

Пилот готов, когда на локальном стенде и на виртуальном хостинге выполняются все пункты:

1. `setup.php` создаёт таблицы ядра и первого администратора; после `install.lock` отвечает 404.
2. `/admin/apps` показывает «Новости» не установленными; «Установить» создаёт таблицы раздела, две
   строки журнала, `version = 1.0.0`, три стартовые рубрики.
3. Отказ установки при `requiresCore` выше `CORE_VERSION` даёт человеческий текст, таблицы не создаются.
4. Повторная установка не дублирует строки журнала; «Обновить» появляется только когда `version` в
   базе ниже версии манифеста.
5. Аноним на `/news/admin/**` получает 403 или редирект на `/login`; страницы раздела несут
   `noindex` и `no-store`; `robots.txt` закрывает приватные пути.
6. Редактор входит, видит сводку со счётчиками и «закреплено N из M материалов».
7. Черновик без текста сохраняется; печать без текста запрещена и в форме, и кнопкой списка.
8. Отказ сохранения (например, занятый адрес) возвращает набранный текст в форму.
9. Публикация делает материал видимым в ленте, на странице рубрики, на странице тега и в `sitemap.xml`.
10. Снятие с публикации убирает материал с сайта и сохраняет срок.
11. Закреплённый материал идёт первым в ленте и в рубрике.
12. Смена адреса даёт 301 со старого на новый; старый адрес запоминается, лимит 10 соблюдается.
13. Назначенный к публикации материал не виден до срока и виден во вкладке «Ждут срока».
14. Рубрика: переименование не меняет адрес, описание читается на её странице, скрытие убирает
    материалы из общей ленты, удаление непустой отказывает с понятным текстом, порядок меняется кнопками.
15. Тег: переименование сохраняет адрес, удаление тега с материалами отказывает, создать тег в
    справочнике нельзя.
16. Поиск в списке материалов работает с первого ввода, `%` и `_` ищутся как текст.
17. Все формы работают без JavaScript (проверка отключённым JS в браузере). **Не проверено локально:
    прогон с отключённым JavaScript на стенде хостинга не выполнялся, пункт остаётся открытым.**
18. Адаптивность 360…1440 и зоны нажатия ≥ 44 px на всех экранах раздела и ядра.
19. Ворота качества (`bash scripts/gate.sh`) зелёные: свежесть стилей, `php -l`, PHPStan 6,
    PHP-CS-Fixer, PHPUnit — без собственных замечаний; пропусков ровно столько, сколько объявлено.
20. На виртуальном хостинге те же проверки повторяются; письма в пилоте не отправляются, но SMTP-контур
    проходит локальную проверку на заглушке и проверку против настоящего сервера хостинга (пункт 13.6).
    **Не проверено локально, требует стенда хостинга: боевого домена с TLS, терминируемым на веб-сервере
    хостинга, в этом репозитории нет.**

## 16. Риски

| Риск | Что делаем |
|---|---|
| Хостинг не даёт перенести документ-корень на `public/` | Запасная раскладка с защитным `.htaccess` в `deploy.sh`, оба режима проверяются после заливки |
| Нет Argon2id | Фолбэк на bcrypt в `core/auth.php`, проверка зондом |
| Исходящий порт 587 закрыт | Почта домена на 465/587; в пилоте писем нет, риска для приёмки не создаёт |
| MySQL 5.7 вместо 8.0 | `JSON` есть и в 5.7; `utf8mb4`-индексы короче 191 символа, поэтому `slug` 60 и `email` 190; `CHECK` не используем |
| Лимит 1024 МБ на процесс | Сборки на сервере нет; перенос данных — только локально |
| Нет Node на сервере | CSS собран и лежит в репозитории, свежесть проверяется воротами |
| PHP-сессии на shared-хостинге чистятся | Срок 8 часов; черновики пишутся в базу сразу, повторный вход данных не теряет |
| Перенос правил по памяти | Источник — `english-portal/src/apps/news` и его тесты; каждая задача называет файл-эталон |
| Тихое самоисключение стража (ноль файлов проверено, ворота зелёные) | Пустой список файлов — падение ворот; обход каталога реальный (`RecursiveDirectoryIterator`), а не `**` в glob; сила стража проверяется равноправными формами нарушения |
| Пропуск важного теста под видом «нет окружения» | Число пропусков в воротах известно и фиксируется; интеграция SMTP обязана исполняться, отказ без настроенного сервера — единственный пропуск |
