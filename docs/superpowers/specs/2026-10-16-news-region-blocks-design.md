# Блоки вывода новостей на страницы — дизайн слоя

**Дата:** 2026-10-16
**Статус:** разделы 1–6 подтверждены в мозговом штурме, ждёт вычитки человеком
**Задача:** #287
**Основание:** спецификация пилота `2026-10-06-php-cms-pilot-design.md` §5 (точки расширения вместо
правок ядра) и §8 (раздел «Новости» живёт в `apps/news`); этот слой ничего в пилоте не переопределяет,
он добавляет в ядро одну точку расширения и в раздел — один экран настроек.

## Принятые решения штурма (перечень, чтобы не переспрашивать)

1. Форма точки расширения — **подход А, помощник-фильтр**: печатающий помощник `region()` в ядре,
   содержимое подставляет цепочка фильтров `region_<имя>`. Печатающий экшен и реестр блоков в ядре
   отклонены (см. раздел 1).
2. Точкой вставки владеет ядро, и ядро не знает ни слова «новости», ни перечня зон.
3. Три зоны: `home`, `category`, `article`.
4. Вызовы ставятся в **пять** шаблонов: главная, лента, рубрика, метка, карточка. Зона `category`
   работает на всех трёх страницах-списках.
5. Пустая зона исчезает целиком — обёртка не печатается, страница без блоков остаётся байт-в-байт
   прежней. Тот же исход у блока с потерянной целью.
6. Вид `related` переезжает из печатного виджета в блок; ради этого `region()` получает **третий
   аргумент** — массив данных страницы. Состояние процесса вместо него и отмена переезда отклонены.
7. Значения `zone`/`kind` в базе — `VARCHAR` с перечнем в коде, не `ENUM`; заводские блоки заводятся
   релизом схемы, не `seed.php`.
8. Блок привязан только к зоне (без условия «только эти материалы» / «кроме этих»), и в одной зоне не
   больше **шести** блоков: предел в константе, проверяется редактором и стоит в SQL.

## Границы слоя (чего он не делает)

- Не делает конструктора страниц. Реестр блоков в ядре, страница как объект и её адрес — будущий слой,
  требующий, чтобы ядро знало форму записей раздела; здесь ядро не знает.
- Не добавляет видов блоков, кроме `list` и `related`. Галерея, цитата, форма заявки и прочее из прежнего
  портала к news-блокам не переносятся.
- Не трогает карту сайта, `robots.txt`, метаданные и рассылку: блок не создаёт новых адресов, он ссылается
  на материалы, которые карта уже отдаёт.
- Не вводит ролей: экран раздела сидит на том же праве, что остальные экраны раздела.
- Не кэширует выборку и не переписывает существительные читателя ленты: `inCategory()`, `relatedLinks()`
  и `categoryFeedRows()` остаются как есть.

## 1. Регион в ядре

Ядро получает одну функцию рядом с `partial()` и `render()` — в `core/template.php`, там же, где живут
оба помощника вывода.

```php
// region() — точка расширения страницы: содержимое подставляет цепочка фильтров `region_<имя>`.
// Пустая зона не печатает ничего, включая обёртку: страница без настроенных блоков остаётся
// байт-в-байт такой, как была до этого слоя.
/** @param array<string, mixed> $data */
function region(string $name, array $data = []): void
{
    $html = (string) applyFilters('region_' . $name, '', $name, $data);

    if (trim($html) === '') {
        return;
    }

    echo partial('region', ['zone' => $name, 'content' => $html]);
}
```

Разметка обёртки (`<section class="region region-<имя>">`) живёт в `core/templates/region.php`, а не
литералом внутри `region()`: сборка стилей читает только объявленные каталоги разметки, и страж
`StyleSourceTest::testРазметкаНеРастётВнеОбъявленныхКаталогов` краснеет на `class=` в `core/template.php`
(вердикт Р5 плана).

Три решения, зафиксированные в этой сигнатуре:

- **Фильтр, а не действие.** Значение фильтра — накопленный HTML: подписчик получает строку и возвращает
  строку со своим содержимым. При действии ядро не видит, напечатали что-нибудь или нет, и проверку пустоты
  с печатью обёртки пришлось бы повторять каждому подписчику или оборачивать в `ob_start()`/`ob_get_clean()`
  — новый класс дефектов (сброшенный чужой буфер, вложенность) ровно там, где у репозитория уже есть
  отдельный страж канала ошибок. Механика есть: `applyFilters()` без подписчиков возвращает входное значение
  (`core/hooks.php:51-62`), поэтому «раздел выключен», «в зоне нет блоков» и «блок потерял цель» дают пустую
  строку одним и тем же кодом.
- **Имя и данные страницы — отдельными аргументами.** Второй аргумент (`$name`) нужен, чтобы один обработчик
  раздела обслуживал несколько зон одной функцией, а не заводил по замыканию на имя. Третий (`$data`) нужен,
  чтобы зона `article` узнала текущий материал: вид `related` — это подборка рубрики за вычетом самой статьи,
  а исключение ниоткуда, кроме страницы. Ядро ключи `$data` не разбирает и не знает ни одного из них.
- **Проверка через `trim()`, а не `=== ''`.** Подборка собирается вызовами `partial()`, которые заканчиваются
  переводом строки, поэтому «пустой» регион фактически равен строке из пробельных символов.

Канал вывода. `region()` делает только `echo`, без заголовков и без `http_response_code()`, поэтому работает
в обоих путях ответа: и `render()` (`core/template.php:64-94`), и `renderToString()` (`core/template.php:103-109`),
который печатает тот же каркас в буфер. Путь совпадает с уже используемым `doAction('page_head')`.

Экранирование. `$name` — литерал шаблона, никогда пользовательский ввод, но проходит через `e()`. `$html`
производится серверным кодом раздела по тому же правилу, что `$page['head']` (`core/template.php:75-77`):
значения материалов печатаются через `e()` внутри карточки, и в регион не уходит строка из настроек напрямую.

## 2. Данные: таблица, релиз схемы, версия манифеста

Настройки живут в таблице раздела `tbl_news_block`. Релиз — `apps/news/sql/20261016_0003_blocks.sql`,
версия манифеста `apps/news/manifest.php:10` растёт с `1.0.0` на `1.1.0`. Ядро считает план обновления по
отсортированному обходу `apps/*/sql/*.sql` и журналу (`core/migrations.php:21-86`), поэтому кнопка «Обновить»
в реестре подхватит файл без правок ядра.

| столбец | тип | назначение |
|---|---|---|
| `id` | `VARCHAR(26) NOT NULL PRIMARY KEY` | общий формат идентификаторов проекта (`core/id.php`) |
| `zone` | `VARCHAR(32) NOT NULL` | имя зоны: `home`, `category`, `article` |
| `kind` | `VARCHAR(32) NOT NULL` | вид блока: `list` (подборка), `related` (похожие к текущему материалу) |
| `title` | `VARCHAR(120) NOT NULL` | заголовок, печатается над списком |
| `target_kind` | `VARCHAR(16) NULL` | `category`, `tag` или `NULL` (вся лента) |
| `target_id` | `VARCHAR(26) NULL` | id рубрики или тега |
| `take_limit` | `TINYINT NOT NULL DEFAULT 5` | сколько материалов показывать |
| `visible` | `TINYINT(1) NOT NULL DEFAULT 1` | показывать ли блок, чтобы не удалять на время |
| `order_index` | `INT NOT NULL DEFAULT 0` | плотный 1..N внутри зоны, значение по умолчанию как у рубрик |
| `created_at`, `updated_at` | `DATETIME NOT NULL` | те же типы и штампы, что у двух существующих таблиц (`utcStamp(nowUtc())`) |
| `KEY news_block_zone_order (zone, order_index)` | | одна выборка зоны покрывается одним индексом |

Три спорных места закрыты так:

- **`VARCHAR`, а не `ENUM`.** Перечень значений держит код, и он один: константы `NEWS_BLOCK_ZONES` и
  `NEWS_BLOCK_KINDS`. Это же правило уже стоит на `status VARCHAR(16)` в `tbl_news_item`
  (`apps/news/sql/20261006_0002_items.sql:15`). `ENUM` заставил бы дублировать перечень в схеме и требовал бы
  `ALTER TABLE` на каждое новое имя зоны.
- **На `target_id` нет `FOREIGN KEY`.** Ссылка полиморфна (рубрика или тег), один внешний ключ на две таблицы
  не выразить, а `CHECK` на виртуальном хостинге недоказуем. Цена честная: удаление рубрики оставляет висячую
  ссылку. Именно поэтому принято решение 5: на публичной странице такой блок молчит, а в админке строка помечена
  «цель недоступна» и остаётся редактируемой. Удаление рубрики при этом не упирается в `RESTRICT`.
- **Заводские значения — релизом схемы, не `seed.php`.** Чтобы сайт, обновляющийся с `1.0.0`, получил те же
  строки, что и свежая установка, одной дорогой. Файл идемпотентен: `CREATE TABLE IF NOT EXISTS` и `INSERT IGNORE`
  с литеральными id (DDL в MySQL фиксируется сразу, журнал пишется по файлам, поэтому файл мог быть начат и
  не дописан — тот же довод, что в `20261006_0001_catalog.sql:2-3`). Две строки: «Похожие материалы» в зоне
  `article` и «Свежие материалы» в зоне `home`, по пять материалов, без цели. `apps/news/seed.php` к блокам
  не прикасается.

## 3. Зоны, имена и места вставки

Имена зон — ключ настроек, а не маршрутов. Ядро не знает ни перечня, ни слова «новости»: перечень живёт в
`apps/news/lib/constants.php`, и тот же перечень читает редактор.

```php
const NEWS_BLOCK_ZONES = ['home', 'category', 'article'];
const NEWS_BLOCK_KINDS = ['list', 'related'];
const NEWS_BLOCK_PER_ZONE = 6;
```

| зона | шаблон | место |
|---|---|---|
| `home` | `theme/home.php` | хвост `<section class="py-8">`, после ссылки на `/news` |
| `category` | `apps/news/templates/feed.php` | после `partial('news/partials/list', …)` |
| `category` | `apps/news/templates/category.php` | то же |
| `category` | `apps/news/templates/tag.php` | то же |
| `article` | `apps/news/templates/single.php` | после списка тегов, перед закрывающим `</article>` (здесь же сидел прежний виджет «Читайте также», снят при переезде) |

Инвариант: зона — всегда хвост основного содержимого, после того, что нарисовало само приложение. Пагинатор
живёт внутри частичного списка (`apps/news/templates/partials/list.php:19`), поэтому блок на странице-списке
стоит под ним. Вызовы печатающие, поэтому не попадают в частичные шаблоны, возвращающие строку: `partial()`
собирает вывод, `region()` его печатает.

Зона `category` одна на три страницы-списка: настройка означает «страница со списком», и у человека в редакторе
есть один предсказуемый ответ на вопрос «куда встанет блок». Четвёртое имя для меток не вводится; если пожелание
«на метках другие блоки» появится, имя добавляется аддитивно и уже настроенные значения не трогает.

Вызов на карточке передаёт данные страницы:

```php
<?php region('article', ['slug' => (string) $item['slug'], 'category' => (string) $item['categorySlug']]); ?>
```

Главная и списки зовут `region()` без второго аргумента.

## 4. Читатель блоков и подписка раздела

Новый файл `apps/news/lib/blocks.php`, подключается в `apps/news/lib/boot.php` сразу после `feed.php` — он
пользуется `toCard()`, `feedScope()` и `takeLimit()`. `apps/news/routes.php:7` подключает `boot.php` целиком,
поэтому вписывать новый файл куда-то ещё не нужно.

Три функции:

```php
/** @return list<array<string, mixed>> */
function newsBlockRows(string $zone): array;

/** @return list<array<string, mixed>> */
function blockFeedRows(array $filter, string $excludeSlug, int $take): array;

function newsRegionHtml(string $html, string $zone, array $data = []): string;
```

- `newsBlockRows()` — одна выборка на страницу: `SELECT … FROM tbl_news_block WHERE zone = ? AND visible = 1
  ORDER BY order_index LIMIT 6`. Ограничитель стоит и в SQL, и в проверке редактора: строка, попавшая в базу
  мимо редактора, страницу не раздурует.
- `blockFeedRows()` — собирается поверх `feedScope()` (`apps/news/lib/feed.php:163-216`): берёт `from`, `where`
  и `args`, где уже лежат правила видимости и `c.visible = 1`, добавляет `AND i.slug <> ?` для исключения и
  `ORDER BY … LIMIT …` из существующих помощников. Правило видимости не заводится вторым экземпляром — тот же
  довод, что держит `inCategory()` (`apps/news/lib/feed.php:497`) и `relatedLinks()` (`:508`) в одном
  теле `categoryFeedRows()` (`:463-488`) — правило видимости живёт там один раз.
- `newsRegionHtml()` — обходит блоки зоны, для каждого просит карточки и печатает заголовок плюс сетку через
  существующий `partial('news/partials/card', …)`, то есть карточка блока и карточка ленты визуально не
  расходятся и не расъезжаются позже. `target_kind = NULL` — вся лента, `category` и `tag` — `feedScope` с
  соответствующим слагом: фильтр ждёт слаг, а в базе лежит id, поэтому слаг берётся через `findCategory()` и
  `findTag()`. Вид `related` просит `blockFeedRows` с рубрикой и слагом из `$data`. Если карточек нет —
  возвращается входная строка без изменений: заголовок не печатается над пустым списком.

Подписка — в `apps/news/routes.php` рядом с фильтром `sitemap_urls` (`apps/news/routes.php:48`), циклом по
перечню зон, и с проверкой активности раздела внутри обработчика:

```php
foreach (NEWS_BLOCK_ZONES as $zone) {
    addFilter('region_' . $zone, 'newsRegionHtml', 10);
}
```

`newsRegionHtml()` первой строкой проверяет `isAppActive('news')` и возвращает вход без изменений. Проверка
обязательна по той же причине, что у фильтра карты сайтов: таблиц раздела может не быть в сборке, а запрос к
несуществующей таблице — это ошибка, а не пустой список.

Стоимость. Одна выборка блоков плюс по одной на каждый блок: главная с двумя заводскими блоками — три запроса,
худший случай (шесть блоков) — семь. Альтернатива «одна большая выборка, объединяющая все блоки зоны» экономит
несколько кругов к базе, но уводит правило видимости из `feedScope()`; на виртуальном хостинге семь простых
запросов дешевле, чем поддержка второй копии правил.

## 5. Экран «Блоки» в админке раздела

**Маршруты.** Два, по образцу справочников (`apps/news/routes.php:38-41`): `GET /news/admin/blocks` →
`newsAdminBlocks`, `POST /news/admin/blocks` → `newsBlocksAction`; оба с `['app' => 'news', 'private' => true,
'permission' => 'login']` — отдельной роли у раздела нет. Пути пишутся строковыми литералами, не константами:
страж `CsrfCoverageTest::postHandlers()` ищет POST-обработчик регуляркой по литералу пути, и путь в константе
исчез бы из-под проверки токена незаметно (`apps/news/routes.php:27-30`). Статические пути маршрутизатор
ставит раньше параметрических, поэтому адрес материала не перехватит экран раздела — как сейчас с `/news/admin`.

**Вкладка.** Пятый пункт в `NEWS_ADMIN_TABS` (`apps/news/lib/admin.php:27`), который обходит `newsAdminNav()`
(`apps/news/lib/admin.php:125-142`): зона нажатия 44 px и отмеченная активная вкладка достаются новому экрану
готовыми.

**Экран — три таблицы, по одной на зону.** Причина: `order_index` плотный внутри зоны, и в общей таблице человек
не видит, относительно чего он двигает блок. В строке: заголовок, вид, цель (или «вся лента»), сколько материалов,
состояние показа, стрелки вверх/вниз, удалить. Над каждой таблицей — форма добавления, где `zone` уезжает скрытым
полем: зона выбирается там, где человек стоит, а не дописывается потом. Пометка «цель недоступна» стоит в строке,
блок остаётся редактируемым.

**Действия** — `match` по `op` с `csrfCheck()` первой операцией и `finishAppAction()` в конце, ровно как в
`apps/news/actions/catalog.php:20-42`: `create`, `rename`, `retarget`, `limit`, `show`, `hide`, `up`, `down`,
`delete`; неизвестное намерение — общий текст отказа без содержимого запроса (`catalogUnknown()`). Ключ
уведомления читается в переменную `$notice` и только потом уходит вызову — иначе `NoticeKeyTest` прочитал бы
литерал как ключ ядра, а тексты раздела живут в словаре раздела.

**Что проверяет запись** — один слой функций в `lib/blocks.php`, вызываемый и экраном, и действиями:

- `zone` ∈ `NEWS_BLOCK_ZONES`, `kind` ∈ `NEWS_BLOCK_KINDS`: чужая строка из POST не записывается, даже если
  обошла редактор;
- `title` — через `collapseSpace()` и предел поля по образцу `checkCategoryTitle()`
  (`apps/news/lib/catalog.php:71`); дубликат заголовка внутри зоны не запрещён (две «Свежие материалы» —
  легальная настройка);
- `take_limit` — сверяется с `takeLimit()` (`apps/news/lib/feed.php:73`): просят 999 — отказ, а не тихое
  зажатие до предела; просят ноль — отказ;
- цель — `categoryExists()` (`apps/news/lib/catalog.php:103`) для рубрики, существование тега для метки;
  `kind = related` цели не имеет вовсе, и сочетание «похожие + цель» — противоречие, отказ;
- предел зоны — перед `create` считается число блоков зоны (видимых и скрытых вместе), седьмой не записывается
  с текстом «в зоне уже шесть блоков».

**Стрелки.** Механика `moveCategory()` (`apps/news/lib/catalog.php:299-331`) переносится с одной поправкой:
обход порядка идёт с `WHERE zone = ?`. Без этого условия движение блока в зоне `home` пересобирало бы порядок
и в зоне `article`, а плотность 1..N осталась бы только в среднем. На верхней строке `up` возвращает пометку
`topped`, на нижней `bottomed` — те же исходы, что у рубрик, без отказа.

**Журнал.** `news.block_saved`, `news.block_moved`, `news.block_deleted` по образцу `news.category_moved`
(`apps/news/lib/catalog.php:328`); в записи идентификатор и намерение, без содержимого полей.

## 6. Проверки, стражи и критерии приёмки

**Новые проверки.**

- `tests/unit/TemplateTest.php` — контракт региона: без подписчиков `region('home')` не печатает ни байта,
  включая обёртку; с подписчиком печатается ровно одна обёртка с классом `region region-<имя>`; третий аргумент
  доходит до обработчика тем же массивом; вывод `region()` попадает в строку, возвращённую `renderToString()`;
  строка из одних пробелов обёртки не печатает.
- `tests/unit/NewsBlockRulesTest.php` — валидации записи: чужая зона, чужой вид, `take_limit` 0 и 999, `related`
  с целью, седьмой блок в зоне, отсутствующие рубрика или тег в цели. Каждый отказ — своим текстом.
- `tests/db/NewsBlocksTest.php` — читатель: блоки зоны идут в порядке `order_index`; скрытый блок не участвует;
  блок с удалённой целью даёт пустую строку (не исключение и не заголовок без списка); подборка не показывает
  черновик и материал, наступивший позже срока, то есть правило видимости работает сквозь `feedScope()`;
  «похожие» не содержат саму статью; выборка зоны упирается в шесть строк, даже если в базе семь.
- `tests/http/NewsPublicTest.php` и `tests/http/NewsAdminTest.php` — на главной после настройки появился заголовок
  блока и ссылка на материал; на карточке заголовок «Похожие материалы» ровно один раз, а прежний
  «Читайте также» снят вместе с виджетом (переезд не оставил второй копии);
  `/news/admin/blocks` без входа — отказ с `Cache-Control: no-store`, как остальные экраны раздела; действие экрана
  без токена отклоняется и ничего не меняет в базе.

**Что закрепляют существующие стражи** (правки — только там, где они не видят новый код; подавлений и ignore-
правок не заводим):

- `CsrfCoverageTest` — новый POST-обработчик объявлен литералом пути, токен проверяется первой операцией, каждая
  форма экрана несёт `method="post"` и `csrfField()`;
- `AppActionContractTest` — в таблице `ACTIONS` (`tests/guard/AppActionContractTest.php:15`) появляется строка на
  `apps/news/actions/blocks.php` с новой константой подписей `NEWS_BLOCK_OP_LABEL` и именем функции отказа; без неё
  новый файл действий стоял бы вне проверки «кнопка без ветки `match` мертва»;
- `NewsVisibilityTest` — новая функция, читающая `tbl_news_item`, обязана звать `visibleWhere()` или быть признанным
  делегатом. Она зовёт `feedScope()`, а тот зовёт `visibleWhere()` (`apps/news/lib/feed.php:180`), поэтому в страж
  дописывается `feedScope()` как признак делегирования: перечень «кто читает столбцы материала» становится шире,
  белый список записей с причиной не пополняется;
- `SqlSafetyTest` — выборки блоков идут плейсхолдерами, `LIMIT` — целым из `takeLimit()` и константы предела, как
  уже делает `categoryFeedRows()`; строка POST в текст SQL не попадает;
- `NoticeKeyTest` и `tests/db/NewsNoticeCoverageTest.php` — новые ключи уведомлений в словаре раздела, вызовы через
  переменную;
- `RouteHandlersTest` — у обоих новых маршрутов есть обработчик, путь `/news/admin/blocks` закрыт в `robots.txt`
  существующим префиксом `/news/admin`;
- `TapTargetTest` — каждая кнопка и ссылка нового экрана имеет зону нажатия 44 px, включая стрелки и переключатель

- `StyleSourceTest` и сборка стилей — класс `region` печатается ядром, поэтому правило для него объявляется в

  добавили, артефакт не пересобрали»; правило, которого нет в разметке, страж мёртвых правил не пропустит;
- `tests/guard/AssetWeightTest.php` — вес артефакта после одного нового правила снимается замером до и после;
- `AppSqlTest`, `tests/db/NewsSchemaTest.php`, `tests/db/MigrationsTest.php` — новый релиз схемы: имена столбцов,
  идемпотентность (`CREATE TABLE IF NOT EXISTS`, `INSERT IGNORE`), версия манифеста `1.1.0`, план обновления из
  одного файла, работа кнопки «Обновить» в реестре;
- `DateUsageTest` — дата берётся из `nowUtc()`, новых способов форматирования не появляется.

**Чем доказывается сила каждой новой проверки.** Каждое утверждение сопровождается обратным замером с мутацией и
возвратом: убрать `trim()` — краснеет тест пробельной строки; снять проверку `isAppActive('news')` — краснеет тест
сборки без раздела; вырезать `visible = 1` из выборки блоков — краснеет db-тест скрытого блока; снять `WHERE zone = ?`
у стрелок — краснеет тест порядка внутри зоны; удалить у кнопки класс блочного вывода — краснеет `TapTargetTest`;
вынуть один каталог из `@source` и не пересобрать артефакт — краснеет `StyleSourceTest`. Если мутация не краснит,
чинится проверка, а не формулировка в отчёте.

**Критерии приёмки.**

1. Деревья без единого блока и с блоками, настроенными в выключенный раздел, отдают байт-в-байт прежние страницы:
   ни обёртки, ни лишнего перевода строки.
2. Раздел «Новости» выключается в реестре — публичные страницы остаются живыми и без ошибок в журнале.
3. Схема поднимается двумя дорогами: свежей установкой и обновлением с `1.0.0`; обе дают одинаковые две заводские
   строки.
4. Экран раздела позволяет создать, переименовать, перенацелить, изменить число, скрыть, передвинуть и удалить блок;
   каждое действие возвращается на тот же экран с внятным уведомлением.
5. Седьмой блок в зоне не создаётся, а уже записанный мимо редактора лишней строкой на страницу не выходит.
6. Ворота (`scripts/gate.sh`) зелёные, включая шаги стилей, синтаксиса и всех стражей; проверка адаптивности
   проходит на экране блоков и на публичных страницах с блоками на ширине 360 px.

**Что осталось непроверенным на этапе дизайна.** Поведение зоны при двух подписчиках одной зоны из разных
приложений (в пилоте подписчик один, порядок задаётся приоритетом и очерёдностью регистрации), и вес страницы при
шести блоках с обложками — это замер на приёмке, а не утверждение проекта.
