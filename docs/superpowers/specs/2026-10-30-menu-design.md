# Меню шапки и подвала из базы — дизайн слоя

**Дата:** 2026-10-30
**Статус:** решения штурма записаны, ждёт вычитки человеком
**Основание:** спецификация `2026-10-10-cms-final-specification.md` §17; дизайн страниц
`2026-10-29-pages-design.md` (п. 5/§7: «Меню — отдельным заходом следом, таблица по образцу
`MenuItem`»); источник — `archives/english-portal` (`prisma/schema.prisma`: `MenuItem`;
`src/server/menu.ts`, `src/lib/menu.ts`, `src/components/content/menu-editor.tsx`,
`src/core/apps/registry.ts` `appNavLinks()`); прецедент — только что закрытый слой страниц.

## Принятые решения штурма (перечень, чтобы не переспрашивать)

1. **Меню живёт в ядре**, как страницы: навигация — способность сайта, а не раздел. Таблица
   `tbl_menu_item` идёт релизом `sql/0003_menu.sql` (ядро применяет SQL из `sql/`,
   `coreSqlPending()`/кнопка «Обновить» — существующий механизм). Установки кнопкой и
   выключения у слоя нет.
2. **Плоский список, не дерево** — ровно как `MenuItem` портала: слот (`HEADER`/`FOOTER`),
   подпись колонки (`section`, только для подвала), `label`, `href`, `blank`, порядок,
   `visible`. Колонки подвала группируются по `section`; иерархии пунктов в портале нет, и
   выдумывать её не нужно — вложенные меню CMS-школе не требуются.
3. **Колонка порядка — `sort`, а не порталово `order`**: ORDER — reserved-слово MySQL, и без
   переименования каждый запрос просил бы backticks (тот же мотив, что `sec_key` вместо `key`
   в слое страниц). Дату создания не веду: у пункта меню нет даты публикации, порядок живёт в
   `sort`; `updated_at` остаётся — единый стиль ядровых таблиц.
4. **`href` — строка под валидатором портала** (якорь `#…`, внутренний путь `/…`,
   `http(s)://…`, `mailto:`, `tel:`, локальный файл `/…x.ext`), без связи с Page по id:
   админ вписывает адрес текстом, слаги страниц видны в конструкторе. Кривой адрес — отказ
   сохранения с человеческой причиной, а не молчаливая правка.
5. **Ссылки разделов — в манифест, поле `publicNav`**: ядро собирает публичные ссылки
   ВКЛЮЧЁННЫХ приложений из манифестов и дописывает их в шапку (порталово `appNavLinks`:
   «администратор не должен помнить, что доска включена, а пункт вести на 404»). Манифест —
   уже существующий реестр структурных фактов (`adminNav`, `privatePaths`), навигация из него
   того же рода. Статические «Новости» из шапки и подвала снимаются — их заменяет `publicNav`
   news; выключенный news прячет ссылку без миграций. Служебные ссылки (Вход/Админка,
   Карта сайта) остаются в теме статическими — это не контент.
6. **Рендер в теме**: `theme/partials/header.php` и `footer.php` зовут помощники ядра
   `menuHeaderLinks()` / `menuFooterSections()` (новый `core/menu.php`) и рисуют ссылки
   существующими утилитами Tailwind; `region()` не трогается — `region('home')` работает как
   было. Пустое меню день-1 сайт не ломает: шапка = логотип + ссылки разделов + Вход/Админка,
   подвал = Карта сайта.
7. **Админка — один экран** `/admin/menu` (право `login`: контент, как конструктор) с двумя
   картами «Шапка» и «Подвал»: строка пункта — форма правки (подпись, адрес, колонка для
   подвала, чекбокс «в новом окне»), действия выше/ниже/скрыть/удалить — отдельными
   inline-формами (формы не вкладываются друг в друга, образец — секции конструктора); внизу
   каждой карты — форма добавления. Один POST-обработчик с `op`, `csrfCheck()` первым вызовом,
   успех — PRG с ключами `menu_created`/`menu_saved`/`menu_moved`/`menu_deleted` (скрытие
   делит ключ с сохранением — и то и другое сохранение пункта).
8. **Перестановка — обмен с соседом и пересборка порядка** 0,1,2… по всему слоту одной
   транзакцией (порталово `moveMenuItem`): одинаковые `sort` из сида не ломают перестановку,
   приём — читай все строки слота, splice, пиши индексы подряд.
9. **Пределы**: label ≤ 60, section ≤ 60, href ≤ 300 (по порталову `menuDraftSchema`),
   `sort` ≤ 999; чтение меню — `LIMIT 500` по конвенции стража производительности. Кэша нет —
   две выборки на страницу дешевле разветвлённой инвалидации.
10. **Сидов нет**: у портала сиды — четыре якоря лонгрида одного сайта; у CMS страницы создаёт
    конструктор, и день-1 меню пусто — безопасно (решение 6). Якоря валидатором пропускаются:
    секция страницы с заполненным якорем даёт адрес `#<sec_key>` на той же странице.

## Границы слоя (чего он не делает)

- Не делает выпадающих подменю (дерева пунктов) и активного состояния пункта — в портале их
  нет; `aria-current` админ-меню — отдельная история админки, не сайта.
- Не делает выбор страницы из списка (пикер): адрес вписывается текстом, как в портале.
- Не добавляет пунктов в админ-навигацию из меню сайта: админка живёт своими вкладками.
- Не переносит захардкоженные колонки подвала портала (`programs`, `cabinet`) — в CMS их
  заменяют пункты с подписью колонки.
- Не вводит ролей: экран сидит на праве `login`, как остальные контентные экраны `/admin`.

## 1. Схема данных ядра

```sql
CREATE TABLE IF NOT EXISTS tbl_menu_item (
  id VARCHAR(26) NOT NULL,
  slot VARCHAR(16) NOT NULL,            -- HEADER | FOOTER, перечень MENU_SLOTS
  section VARCHAR(60) NOT NULL DEFAULT '', -- подпись колонки подвала; у шапки всегда ''
  label VARCHAR(60) NOT NULL,
  href VARCHAR(300) NOT NULL,
  blank TINYINT(1) NOT NULL DEFAULT 0,
  sort INT NOT NULL DEFAULT 0,
  visible TINYINT(1) NOT NULL DEFAULT 1,
  updated_at DATETIME NOT NULL,
  PRIMARY KEY (id),
  KEY menu_item_order (slot, sort)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

Отличия от портала, каждое — по причине: колонка `order` переименована в `sort` (решение 3);
`id` — VARCHAR(26) под `newId()` (Crockford, как все таблицы CMS); `blank`/`visible` —
TINYINT по стилю ядра; релиз идемпотентен (`IF NOT EXISTS`, MySQL фиксирует DDL сразу).

## 2. Чтение и рендер

- `menuHeaderLinks(): list<array{label, href, blank}>` — видимые пункты слота HEADER по
  порядку (сортировка `sort asc, label asc` — порталово `byOrder`), следом ссылки
  ВКЛЮЧЁННЫХ приложений из `publicNav` манифестов (`blank => false` — в новом окне разделы
  сайта не открывают).
- `menuFooterSections(): list<array{title, links}>` — те же строки слота FOOTER,
  сгруппированные по `section`; пустая подпись → `MENU_SECTION_FALLBACK` («Ссылки»). Колонка
  занимает место своего первого пункта (порталово `groupBySection`): строки уже отсортированы.
- Тема печатает ссылки через `e()`, blank — `target="_blank" rel="noopener noreferrer"`
  (существующий приём кнопок секций).

## 3. Админка

Маршруты: `GET/POST /admin/menu`, метки `['private' => true, 'permission' => 'login']`.
Экран: две карты; в каждой — строки пунктов в порядке слота (у подвала с подписью колонки),
у каждой строки форма правки (`op=save-item`) и inline-формы действий (`op=move-item` с
направлением, `op=toggle-item`, `op=delete-item`), внизу форма добавления (`op=create-item`
со скрытым слотом). Отказ (кривой href, кривой label) — flash-причина, механика
`finishAppAction` с ключом `migration-failed`, как у конструктора.

- `tests/db/MenuTest.php` — операции на живой базе: создание в конец, правка, перестановка
