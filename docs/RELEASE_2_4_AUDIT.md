# Аудит: система тем и шаблонов (Theme & Template Studio)

Документ отвечает на вопрос «реализованы ли темы и шаблоны для сайта и страниц» по факту
содержимого репозитория, а не по планам. Каждое утверждение ниже проверено чтением кода и
прогоном стражей; номер строки или имя файла указаны там, где это важно.

## 0. Нумерация релизов: коллизия и решение

Мастер-промпт называет эту работу «RELEASE 2.3 — Theme & Template Studio». В репозитории
номер **2.3 уже занят**: `docs/RELEASE_2_3.md` — «Конструктор контента» (пользовательские типы
записей, конструктор полей, связи, глобальные блоки), она отгружена, `CORE_VERSION = '1.5.0'`
(`core/version.php`), схема `sql/0005_release23.sql` применена.

Поэтому в коде и документации эта работа идёт как **RELEASE 2.4 «Theme & Template Studio»**,
а «Content Modeling Pro» из второго мастер-промпта — как **RELEASE 2.5**. Номера в мастер-промпте
сдвинуты на единицу относительно репозитория; смысл задач не меняется. Это решение записано
здесь, чтобы не заводить второй файл с тем же именем и не путать журнал схемы.

### 1.2. Иерархия шаблонов

`core/template.php:12` — `themeRoots()` возвращает `['<EXTRA_THEME_DIR>', 'theme']` либо `['theme']`.
`resolveTemplate()` (там же, строка 22) ищет по фиксированной цепочке:

```
apps/<app>/templates/<name>.php  →  theme/<name>.php  →  core/templates/<name>.php  →  theme/404.php
```

`EXTRA_THEME_DIR` — конфигурационная подмена каталога темы, её используют тесты. **Переключения
тем нет**: «тема» — это ровно один каталог `theme/`, второй можно подставить только правкой
`config.php`.

### 1.3. Обвязка сайта

| Что | Где | Факт |
|---|---|---|
| Каркас | `theme/layout.php` | `<main class="mx-auto max-w-5xl px-4 py-8 sm:px-6">` — **ширина зашита** |
| Шапка | `theme/partials/header.php` | Один вариант, логотип и текст из настроек |
| Подвал | `theme/partials/footer.php` | Один вариант, логотип, текст, копирайт |
| Меню | `core/menu.php` | Слоты `header` / `footer`, состав задаёт администратор |
| Настройки сайта | `core/settings.php:9` | `header_logo`, `header_text`, `footer_logo`, `footer_text`, `footer_copyright`, `maintenance_mode`, `maintenance_text` |
| Режим ТО | `core/maintenance.php` | Заглушка 503, сотрудник видит сайт как обычно |
| Палитра | `src-css/app.css` | 6 токенов `@theme`: `--color-paper, cream, accent, good, bad` |

### 1.4. Ширина на всю страницу

**Не реализована.** Секции сами несут внутренний контейнер, и в `theme/` 26 вхождений
`max-w-5xl` (каркас, шапка, подвал, `page.php`, `content-entry.php`, `content-type.php` и 19
секций). Колонка `layout` у секции существует, но обслуживает только `float` и `files`:
`PAGES_KIND_LAYOUTS` (`core/pages.php:172`) содержит два вида, `pagesLayoutOptionsOf()` для
остальных возвращает пустой список.

### 1.5. Предпросмотр и публикация

`core/preview.php` + токены предпросмотра, `core/revisions.php` (ревизии, откат, оптимистичная
блокировка), `core/scheduler.php` (отложенная публикация через `bin/cron.php`). Это готовый
фундамент для предпросмотра шаблонов.

### 1.6. Ворота

`scripts/gate.sh`: свежесть стилей, синтаксис, PHPStan, php-cs-fixer, PHPUnit. Последний полный
прогон по истории — **1914 тестов / 11 100 утверждений / 1 пропуск** (пропуск: почтовая
интеграция без `CMS_SMTP_*`). Стражей разметки, которые придётся соблюсти новой системе:
`StyleSourceTest` (классы обязаны быть в артефакте), `OutputEscapingTest`, `TapTargetTest`
(зоны ≥ 44 px), `AdminFormSpacingTest`, `CheckboxAlignTest`, `FilePickerIconTest`,
`AdminGridOverflowTest`, `ResponsiveCoverageTest`, `ViewportMetaTest`, `NoIndexNoStoreSweepTest`.

### 2.1. Расхождение с «Content Modeling Pro» (RELEASE 2.5 по нумерации репозитория)

Из мастер-промпта 2.4 уже сделано в RELEASE 2.3: типы записей, конструктор полей (9 видов:
`text, textarea, richtext, checkbox, select, image, url, date, relation`), связи, глобальные
блоки, ревизии, публичный показ.

Не сделано: повторяемые поля (`repeatable`), группы полей, условная логика показа, таксономии,
коллекции, глобальные наборы данных, REST API, пользовательские JSON-представления.
Пределы текущего набора: `CONTENT_FIELDS_LIMIT = 40`, `CONTENT_RELATIONS_LIMIT`, `CONTENT_LIST_LIMIT = 200`.

## 3. Целевая архитектура

Ключевое ограничение проекта — **никаких рантайм-зависимостей** (нет Composer-пакетов в
рантайме), PHP 8.3+, MySQL 8, CSP `default-src 'self'`. Отсюда архитектура:

### 3.1. Тема как пакет

```
themes/<slug>/
  theme.json          манифест: slug, name, version, description, colors, fonts, layouts[], supports[]
  layout.php          каркас (обязателен)
  templates/          переопределения шаблонов (необязательно)
  sections/           переопределения секций (необязательно)
  preview.svg|png     скриншот для каталога
```

Реестр тем — `core/themes.php`: чтение каталога, разбор и проверка `theme.json`, активная тема в
`tbl_option` (ключ `theme_active`). `themeRoots()` получает активную тему **первой** в цепочке,
`theme/` остаётся запасной — это сохраняет совместимость: сайт без выбранной темы работает как
сегодня.

**Установка ZIP не входит в первый этап.** Причина: распаковка архива в документ-корень — это
новый класс уязвимостей (zip-slip, symlink, исполняемые файлы), а собственной проверки в проекте
нет. Первый этап — темы, положенные в `themes/` владельцем сайта; установка через админку
отдельным этапом с проверкой путей, белым списком расширений и запретом записи вне `themes/`.

### 3.2. Макет страницы

Новая колонка `tbl_page.layout VARCHAR(40) NOT NULL DEFAULT ''` (миграция
`sql/0006_theme_studio.sql`). Пустое значение = текущий макет, поэтому старые страницы
рендерятся как раньше — требование §25 промпта.

Значения: `default`, `landing`, `full`, `sidebar-left`, `sidebar-right`, `no-header`, `blank`.
`render()` выбирает каркас по макету страницы, а не по единственному `layout.php`.

### 3.3. Ширина секции

Колонка `layout` секции уже есть и уже читается двумя видами. Расширяем её смысл: для всех видов
она становится **шириной** со значениями `''` (standard), `wide`, `full`, `custom`.

Чтобы не править 26 файлов секций вручную и не разойтись с ними, вводится помощник
`pagesSectionContainer(array $section): string` в `core/pages.php` — он возвращает строку
классов контейнера. Секции переводятся на него постепенно; страж `SectionWidthTest` держит
правило «секция не несёт собственный `max-w-5xl` в разметке».

**Full Width** = секция занимает всю ширину окна, внутренний контейнер ограничивает только
содержимое. Фон и отступы остаются у секции.

### 3.4. Шаблоны и паттерны

Макет (layout) — структура каркаса. Шаблон (template) — сохранённый набор секций с настройками.
Паттерн — короткий набор из 1–3 секций. Хранение: `tbl_page_template` (id, slug, title, kind,
sections JSON, created_at) и `tbl_page_pattern` (то же, но короче). Применение шаблона копирует
секции в страницу **через `createSection()`**, а не прямыми INSERT — пределы, уникальность ключа
и формат JSON остаются правилами ядра.

### 3.5. Права

Новая роль не нужна: правка макетов и шаблонов — `admin`; применение шаблона к странице —
`editor` и выше. Проверка через существующий `currentUser()` и `grants`.

## 4. План миграции

1. `sql/0006_theme_studio.sql` — **только дополняющие** изменения: `ALTER TABLE tbl_page ADD COLUMN layout`, `CREATE TABLE IF NOT EXISTS tbl_page_template`, `tbl_page_pattern`. Откат не нужен: новые колонки со значением по умолчанию и новые таблицы старый код не читает.
2. Реестр тем и `themeRoots()` — активная тема первой, `theme/` запасной.
3. Каркасы макетов в `theme/layouts/` — `default.php` (побайтово равен текущему `layout.php`), `landing.php`, `full.php`, `sidebar-left.php`, `sidebar-right.php`, `no-header.php`, `blank.php`.
4. Ширина секций — помощник + перевод секций.
5. Конструктор: селект макета в форме страницы, селект ширины в форме секции.
6. Библиотека шаблонов и паттернов, применение к странице.
7. Документы `docs/RELEASE_2_4*.md`.

Шаги 1–3 не меняют вид ни одной существующей страницы: пустой `layout` = текущий каркас.

## 5. Риски

| Риск | Смягчение |
|---|---|
| Правка 26 секций ломает вид | Помощник возвращает ровно текущую строку при пустой ширине; страж `SectionWidthTest`; выборочный перевод с проверкой на стенде |
| Новый каркас ломает стражей разметки | `ViewportMetaTest`, `TapTargetTest`, `StyleSourceTest` прогоняются на каждом шаге; классы только существующие |
| `ALTER TABLE` не идемпотентен | Проверка `information_schema` перед добавлением колонки; `CREATE TABLE IF NOT EXISTS` для новых таблиц |
| Импорт ZIP открывает zip-slip | Установка ZIP отложена до отдельного этапа с проверкой путей |
| Расхождение с «Content Modeling Pro» | Разделы разведены по номерам (§0), работа идёт последовательно |
